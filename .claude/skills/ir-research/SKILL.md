# IR 調査の手順（Baibai-Loop）

上場企業の開示を調べて trade/research に反映するときの手順。`AGENTS.md` の anti-pattern（AP-01 一次情報 / AP-02 数値検算 / AP-04 schema・意味の読み）と整合させる。`docs/reference/data-sources.md` の Tier 分類が上位ルール。

## 0. 大原則

- **candidate row（`records/04-candidates/`）が screening の canonical fact source**。IR 調査はそれを上書きせず、**補強・source 追加・最新化**に使う。差異が出たら override せず honest に flag する（AP-09）。
- 取得した数値には**必ず source URL** を添える。**1 ソースを鵜呑みにせず最低 2 ソースで相互検算**する（AP-01 / AP-02）。
- 本リポジトリの市況は scenario 設定のことがある。scenario の forward 数値と実 IR が食い違う場合は、どちらが canonical か（通常 candidate row）を明記して併記する。

## 1. まず「何を判定するか」と必要指標を決める

調べ始める前に、判定目的から逆算して取得すべき指標を列挙する。

| 判定目的 | 取得すべき指標 |
| --- | --- |
| trade の invalidation 判定 | 売上(既存店)・**営業利益**・経常利益・営業 CF・**通期予想の据置/修正**。純利益単独で判断しない |
| 配当の下支え | 1 株配当（中間/期末/年間）・配当方針・**連結配当性向**・増減配 |
| net cash / 財務健全性 | 現預金・有利子負債・自己資本比率・会社の財務方針（負債削減姿勢など） |
| 割安の質（valuation trap か） | PER/PBR と同時に成長性・還元・業績モメンタム |

## 2. ソース階層（上から優先）

1. **一次**: 会社 IR ページ / TDnet・EDINET の**決算短信 PDF**（`contents.xj-storage.jp`、`nikkei.com/nkd/disclosure/tdnr/...`）。配当・優待は会社 IR の該当ページ。
2. **準一次（数値の早見に有用）**: 日経会社情報（`nikkei.com/nkd/company/kessan/?scode=XXXX`）、IRBANK（`irbank.net`）、**松井証券 決算**（`finance.matsui.co.jp/stock/XXXX/settlement/index`）、銘柄スカウター（monex）、株予報。
3. **速報（方向感のみ）**: ウエルスアドバイザー決算速報（Yahoo!ファイナンス news）。**見出しで方向、本文は有料のことが多い**。

## 3. 検索クエリの型

`証券コード + 銘柄名 + 期（例「2026年7月期 第3四半期」）+ 知りたい指標（営業利益/経常/通期予想/配当/原料費調整 等）` を日本語で。指標名を変えて 2〜3 回投げ、ソースを散らして相互検算する。

## 4. 落とし穴チェックリスト（今回の実例つき）

- [ ] **見出しの罠**: 「純利益 -10.3% の 2 ケタ減益」だけで構造悪化と即断しない。**営業利益・経常・売上(既存店)・通期予想を必ず分離**して見る。
  - 実例（3539 JMHD 2026年7月期 3Q）: 純益 -10.3% だが**売上は +7.6% 増収**、3Q累計 営業利益は**ほぼ横ばい**。中間期も特損で純益 -11.4% でも営業 +12.7% だった。純益の振れは特別損益のことが多い。
- [ ] **単四半期 vs 累計を分ける**: 累計が横ばいでも単四半期で減益に転じていればモメンタムは劣化。
  - 実例（3539）: 3Q累計 営業 +0.09 億（横ばい）だが、**Q3 単独は営業 -6.21 億の減益**。中間 +12.7% からの減速がここで見える。
- [ ] **複数ソースの矛盾を検算して採否**: 速報見出しと一致する側を採る。
  - 実例（3539）: ある要約は「売上 1,862 億・純益 +18%」、別ソース（松井）は「1,495 億・純益 -10.3%」。速報見出し（-10.3%・1,495 億）と整合する**後者を採用**し、前者は破棄。
- [ ] **単位（億/百万円/billion）の混同**: web 要約は「億」を「billion」と誤記しがち。**百万円 → 億で検算**（例 149,579 百万円 = 1,495.79 億円）。
- [ ] **進捗率と季節性**: 通期予想に対する進捗率を 9/12=75% と単純比較しない。H2 偏重ガイダンス等の季節性を考慮（例 3539: 営業 3Q 75.36/109 = 約 69%、ただし会社は H2 偏重）。
- [ ] **paywall / 403 への対処**: Yahoo VIP・kabutan・minkabu は本文取得不可のことが多い → **松井証券・IRBANK・会社 IR・日経会社情報**で代替する。取れなければ「速報では確認できず・短信要確認」と honest に書く（捏造しない）。
- [ ] **公表日・対象期の確認**（AP-07）: 「2026年7月期 3Q」など FY 末と四半期を取り違えない。決算発表日を控える。

## 5. 記録への落とし方

- 反映先: 監視・決算イベントは該当 **trade record の `## 2. 保有中ログ` に日付つきで追記**（`docs/components/trades.md` §7.2）。thesis の検証・配当確認は **research memo の該当節**に「YYYY-MM-DD IR 一次確認」として追記。
- 書く内容: **数値 + 出所 URL + 判定（invalidation に touch するか）+ アクション**。
- 判定の粒度: 「即時 exit を要する構造破綻」か「review レベル（要監視・上値減退）」かを区別する。売上増・累計営業プラス・財務健全なら通常は後者。
- candidate row は canonical のまま維持し、IR は補強として併記。scenario と実 IR の差異は明記。

## 6. 完了条件

- 判定に必要な指標が**出所つき**でそろい、最低 2 ソースで矛盾なく検算できている。
- 取れなかった項目は「未取得・要短信確認」と明記してある。
- 反映先（trade holding-log / research）に数値・出所・判定・アクションが記録されている。
