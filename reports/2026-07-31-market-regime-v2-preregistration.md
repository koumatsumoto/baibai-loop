# TOPIX ベース market regime v2 の定義 — 事前登録

## 0. 事前登録（レジーム別の較正を実行する前に commit する）

E[r] 実現率がレジームで変わるかを測るには、まずレジームの定義が要る。**定義と閾値をここで固定し、grid search をしない。** 結果を見てから閾値を動かせば、どんな結論でも作れてしまう。

### 入力

TOPIX（指数コード `0000`）の日足終値のみを使う。2016-08-01 から 2,441 営業日が 1 コールで取れることを確認済みで、個別株の取引日カレンダーと日数が完全に一致する。

| 量 | 定義 |
| --- | --- |
| `drawdown` | 直近 252 営業日の高値からの下落率 |
| `return_60d` | 60 営業日リターン |
| `volatility` | 対数リターンの 60 営業日標準偏差を年率化し、直近 5 年（1,250 営業日）内の分位で表す |

3 つとも asof 日までの終値だけから決まり、先の情報を使わない。

### 状態の定義

上から順に評価し、最初に当たった状態を採る。**順序は定義の一部であり、後から入れ替えない。**

| 状態 | 条件 | 意図 |
| --- | --- | --- |
| `stress` | `drawdown <= -15%` | 高値から明確に離れた局面 |
| `recovery` | `drawdown <= -8%` かつ `return_60d > 0` | 底を打って戻り始めた局面 |
| `extended` | `drawdown > -3%` かつ `volatility` 分位 `< 0.5` | 高値圏で市場が静かな局面 |
| `normal` | 上のいずれでもない | 残余 |

閾値の根拠は「一般に語られる調整（−10%）と弱気相場（−20%）の間に stress の線を置き、その手前に recovery を置く」という事前の区分であり、本 panel の結果からは採っていない。

### 採否基準（何をもって「レジームで変わる」と言うか）

E[r] 実現率（予測 E[r] に対する実現 excess の比）をレジーム別に集計し、次を満たすときだけ「レジーム依存がある」と述べる。

1. **標本の確保**: 各レジームに 8 cohort 以上あること。下回るレジームは「観測不足」として数値を出さない。
2. **順序の一貫性**: 1y と 3y でレジーム間の大小関係が同じ向きであること。
3. **効果量**: 最大レジームと最小レジームの実現率の比が 1.5 倍以上あること。

**満たさない場合は「レジーム依存は観測されなかった」と記録する。** いずれの場合も E[r] の実現率パラメータは変更しない（変更には 3y/5y evidence と別の事前登録が要る）。

### 交絡の検定（#685 の反省を条件に含める）

#685 では交絡候補を 1 つだけ当てて止め、より強い交絡を見逃した。ここでは**交絡候補を列挙し、レジーム tag との相関が強い順に当てる**ことを条件に含める。最低限、次を確認する。

- レジームが特定の暦年に偏っていないか（レジームが単に「2020 年」の別名になっていないか）。
- レジーム別の cohort 集合で、母集団の規模・流動性の分布が揃っているか。

### 先に開示する限定

- **盲検ではない。** 拡張 panel が COVID 崩落・金融相場・バリュー期を含むことは既知で、閾値がそれらを分けることは設計時に意図している。分けた結果として実現率が違うかは未知である。
- **cohort は独立でない。** 月次 cohort は forward 窓が重なり、同じレジームの cohort は特に強く重なる。cohort 数を標本数として読まない。
- **レジームは事後に確定する量ではない。** 定義は asof までの終値だけを使うので、当時判定できた状態である。ただし「当時これを見て判断していた」という意味ではない。

## 1. 対象

拡張 grid（2019-11-29〜、80 cohort）の 1y / 3y。

## 2. 計測

TOPIX 10 年（2016-08-01〜2026-07-29、2,441 営業日）で 80 cohort に tag を付けた。

| regime | cohort |
| --- | ---: |
| `normal` | 51 |
| `extended` | 18 |
| `recovery` | 9 |
| `stress` | 2 |

定義は意図した局面を切り出している。`stress` は 2020-03-31（drawdown −19.7%・vol 分位 1.00）と 2020-04-30 の 2 件、`recovery` の 9 件は 2020-05・06・07・10、2022-04・05・07、2025-02、2026-03 である。

E[r] 実現率は「E[r] 最上位 quintile − 最下位 quintile の予測差」に対する「同じ 2 群の実現 excess 差」の比で測る。**順位付けに使う列は `er_reversion_annual`** — `_evaluate_er_calibration` が出荷している軸で、E[r] のうち価格収束成分だけを price-only 実現値へ較正する座標である。事前登録が列名を明示しておらず、当初は `er_annual`（carry 込みの合計）で集計していた。両方を出す。

| regime | 1y `er_reversion_annual` | 1y `er_annual` | 3y `er_reversion_annual` |
| --- | --- | --- | --- |
| `stress` | n=2 **観測不足** | n=2 **観測不足** | n=2 **観測不足** |
| `recovery` | n=8 **+2.757** | n=8 +1.751 | n=7 **観測不足** |
| `extended` | n=14 **+3.230** | n=14 +2.745 | n=8 +3.53 |
| `normal` | n=44 **+2.731** | n=44 +2.401 | n=27 +3.28 |
| **最大 / 最小** | **1.18 倍** | 1.57 倍 | — |

再現コマンド:

```bash
uv run baibai-engine screening calibration-build --start 2019-11-01 --end 2026-06-30 --force
uv run baibai-engine screening calibration-evaluate --horizon 1y --horizon 3y --out /tmp/eval.yaml
# TOPIX: jquantsapi ClientV2.get_idx_bars_daily(code="0000", from/to)
# regime: baibai_engine.screening.calibration.regime_tag.regime_at(closes, asof)
```

### 交絡の検定（事前登録した条件）

レジームが単に暦年の別名になっていないかを確認した。

| regime | n | 年別の内訳 | 最頻年の占有 |
| --- | ---: | --- | ---: |
| `stress` | 2 | 2020: 2 | **100%** |
| `recovery` | 9 | 2020: 4 / 2022: 3 / 2025: 1 / 2026: 1 | 44% |
| `extended` | 18 | 2023: 7 / 2024: 4 / 2025: 4 / 2019: 2 / 2020: 1 | 39% |
| `normal` | 51 | 2021: 12 / 2022: 9 / 2024: 8 / 2025: 7 / 2020: 5 / 2023: 5 / 2026: 5 | 24% |

`recovery` / `extended` / `normal` は複数年に分散しており、暦年の別名ではない。

事前登録したもう 1 つの確認（レジーム別の母集団分布）も出す。

| regime | 母集団中央値 | 時価総額中央値 | 出来高中央値 |
| --- | ---: | ---: | ---: |
| `stress` | 1,192 | 970 億 | 5.10 億 |
| `recovery` | 1,274 | 1,108 億 | 4.95 億 |
| `extended` | 1,432 | 1,146 億 | 4.50 億 |
| `normal` | 1,327 | 1,178 億 | 4.70 億 |

`stress` は母集団が最小・時価総額中央値も最小で、規模分布が他レジームと揃っていない。標本が 2 件しかない以上これ自体を効果とは読めないが、**仮に stress の数値を出していたら規模差と交絡していた**ことは記録しておく。

**`stress` は 2 cohort とも 2020 年で、レジームと「2020 年 3〜4 月」が観測上まったく区別できない。** これは標本不足という以上に識別不能で、仮に stress の実現率が他と違って見えても、それがレジームの効果か COVID 特有の効果かを分ける材料がこの panel には無い。stress について数値を出さない判断は、条件 1（8 cohort 以上）だけでなくこの識別不能性からも支持される。

## 3. 判定

事前登録した 3 条件に照らす。

| 条件 | 出荷軸（`er_reversion_annual`） |
| --- | --- |
| 1. 各レジーム 8 cohort 以上 | `stress` は 1y/3y とも 2 件、`recovery` は 3y で 7 件 — **満たさない** |
| 2. 1y と 3y で順序が一致 | 1y は `extended` > `recovery` > `normal`、3y は `extended` > `normal` — 標本の足りるレジームが揃わず**判定できない** |
| 3. 最大 / 最小が 1.5 倍以上 | 1.18 倍 — **満たさない** |

**「レジーム依存は観測されなかった」と記録する。3 条件すべてを満たさない。** E[r] の実現率パラメータは変更しない。

当初この節は `er_annual` で集計し、条件 3 だけは満たす（1.57 倍）と書いていた。出荷軸で測ると 1.18 倍で落ちる。**事前登録が列名を固定していなかったため、軸の選択に裁量が残っていた。** 次の事前登録では、統計量の定義に列名を含める。

### 「どのレジームでも 1 を超える」とは言えない

中央値だけ見れば 2.7〜3.5 倍だが、**cohort 単位では 12/68 が 1.0 を下回り、4 件が負である**（出荷軸・1y）。しかも散らばっていない。

| 最悪 4 cohort | 実現率 |
| --- | ---: |
| 2019-11-29 | −2.45 |
| 2019-12-30 | −2.29 |
| 2020-01-31 | −2.08 |
| 2020-02-28 | −1.38 |

**これは COVID 崩落を forward 窓に含む連続した as-of であり、`stress` / `recovery` として「観測不足」で数値を伏せた期間と重なる。** 標本不足を理由に数値を出さないまま「レジームを問わず一貫」と書けば、一般化を否定する当の観測を伏せたまま一般化することになる。その記述は撤回する。

言えるのは「**forward 窓が平穏だった cohort では実現率が 1 を大きく超え、崩落を含む cohort では 1 を割ることがある**」までで、それは下の分割が示すとおり entry 時点のレジームでは捉えられない。

### entry 時点のレジームでは、探している効果を捉えられない

`regime_at` が貼るのは **as-of の状態**だが、実現率は **forward 窓の性質**である。同じ 68 cohort を forward 窓中の TOPIX 最大 drawdown で 2 分すると:

| 1y | n | 実現率中央値 |
| --- | ---: | ---: |
| 窓中の drawdown ≤ −20% | 15 | **+1.637** |
| 同 > −20% | 53 | **+3.619** |

1y で 2.21 倍の差が出る。ただし 3y では 3.279 対 3.416（1.04 倍）で消えるので、**この分割も事前登録の条件 2 は満たさない。**

さらに重要な限界として、**この分割は entry 時点では使えない。** forward 窓の崩落は as-of には未知である。したがってこれは「E[r] の実現率を予測する道具」ではなく、「実現率のばらつきの主因が entry 時の相場でなく、その後に何が起きたかにある」という診断である。E[r] の実現率パラメータを変えない判断は、この点からも支持される。

### 観測不足がこの計測の主な限界

10 年の panel に `stress` が 2 cohort しかない。COVID 崩落は 1 度きりで、月次 cohort では 2 点にしかならない。**「下落局面で E[r] の実現率が落ちるか」という最も知りたい問いに、この panel は答えられない。** 答えるには次の stress 局面を待つか、cohort を週次にして点数を増やすかで、後者は forward 窓の重なりをさらに強めるので標本数の見かけを増やすだけになる。

### この結果が意味しないこと

- **E[r] を定数倍して使ってよい、ではない。** 実現率は「予測差に対する実現差の比」で、水準の話ではない。E[r] の絶対値を較正するには別の座標が要る。
- **#308 の「バリュー期 2.4 倍」と直接は比較できない。** あちらの予測 quintile spread は ±2.6% で、本計測の `er_reversion_annual` の予測差レンジ（1y で 0.048〜0.098）と整合するが、集計対象の cohort 集合も期間も違う。同一の統計量として並べない。
- **レジーム定義が無意味だった、ではない。** 定義は意図した局面を切り出しており、`stress` の cohort 数が足りないだけである。次の下落局面で同じ定義を適用すれば点数が増える。
- **cohort は独立でない。** 同じレジームの cohort は forward 窓が特に強く重なる。勝率 1.00 を確率として読まない。
