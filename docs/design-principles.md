# 設計原則

Baibai-Loop における世界情勢調査の設計方針と、その根拠。運用ルール ([workflow.md](./workflow.md))・データソース定義 ([data-sources.md](./data-sources.md))・テンプレート ([templates/](./templates/)) は全てこの原則に従う。

## 分析階層: 世界情勢 → 地域経済 → 個別資産

トレード判断のための調査は、以下の階層で上から順に分析する:

1. **世界情勢**: グローバルマクロ・主要中央銀行・コモディティ・地政学
2. **地域経済**: 対象資産が属する地域の一次統計・金融政策・為替
3. **個別資産**: 対象資産のマーケット指標・セクター動向・個別イベント

現在の主対象資産は日本株のため、具体的には以下となる:

- 世界情勢（グローバル）
- 日本経済
- 日本株

### 根拠

#### 1. 因果の向きに忠実

マクロ経済の因果連鎖は「グローバル → 地域 → 個別」の順に伝播することが多い。例えば「FOMC 金利判断 → USD/JPY → 輸出関連の日本株」という流れ。逆順では説明できないケースが多い。調査もこの順序で行うことで、因果を見落としにくい。

#### 2. 他資産への展開容易性

将来、米国株・欧州株・債券・コモディティなどに対象資産を拡張する可能性がある。その時:

- 「世界情勢」レイヤーは全資産で共有できる
- 「地域経済」レイヤーだけ差し替えれば対応できる
- 「個別資産」レイヤーは各資産固有のテンプレートを用意する

この階層を最初から設計に組み込むことで、将来の展開時にテンプレートを一から作り直す手間を避ける。

#### 3. 日本株バイアスの回避

世界情勢を分析せずに日本株だけを見ると、日本固有要因と海外要因の切り分けができない。階層化により「どの層で起きた変化が日本株に波及したか」を構造的に追える。

## 更新サイクルとファイル粒度の一致

データは更新サイクルごとに別ファイルに分離する:

- **週次更新**: マーケット指標・地政学速報は週次 journal (`world-weekly`) に記録
- **月次更新**: CPI / 雇用統計などの月次統計は月次 journal (`macro-monthly`) に記録
- **イベント時**: FOMC / 日銀 / 主要指標発表は個別 kind で記録

週次/日次の journal は、月次データを再掲せず **月次 journal への参照** で済ませる。更新頻度が違うデータを同じファイルに同居させると、毎週の大半が「先週と同じ値」の羅列になり、メンテナンス負荷が非対称に膨らむため。

## レイヤー分離の運用

- 「世界情勢」レイヤーの指標は、日本株と同時に米国株を分析する際にも流用できるように、日本固有バイアスを含めない
- 「日本経済」レイヤーでは、世界情勢レイヤーで既に扱った指標（例: 米 10Y 利回り）を再掲しない
- 「日本株」レイヤーでは、日本経済レイヤーで既に扱った為替・金利を再掲しない

再掲を避けることで、同じ情報を複数箇所で管理するコストと矛盾リスクを減らす。

## 今後の拡張指針

他資産に展開する場合の想定:

- `templates/world-analysis.md` の「世界情勢」節は各資産で共通化する前提で維持
- 各資産レイヤー用テンプレートを追加（例: `us-stock-analysis.md`, `fx-analysis.md`）
- kind に資産プレフィックスを付与する検討（例: `jp-world-weekly`, `us-world-weekly`）は、実際に他資産を扱い始める時点で議論する

本原則に従わない運用変更を入れる場合は、本ファイルの該当節を先に更新してから運用側を合わせる。
