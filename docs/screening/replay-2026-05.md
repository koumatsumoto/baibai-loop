# Screening profile replay 評価 (2026-05)

`#157` の screening replay / hold-out / forward return 評価。`strict` / `balanced` / `loose` profile を週次 candidates に replay し、各 profile の recommended queue の forward return を日経225 ETF proxy 比で比較する。再実行手順は [`../operations/screening-runbook.md`](../operations/screening-runbook.md) §Multi-week replay。

## 算出方法と価格基準

- ツール: `baibai-loop-ledger screening-replay`（`forward_return` + `screening_replay` モジュール）。
- forward horizon: asof + 1w / 4w / 8w（暦週、`asof + weeks*7` 日を on/before で解決）。
- 価格基準: J-Quants 日足を `resolve_price_on_or_before` で解決（adjusted close 優先、無ければ close_unadjusted）。entry / forward / benchmark を同一 basis に揃える。
- benchmark: 日経平均は J-Quants 未収録のため ETF proxy `1321`（野村 日経225 ETF）。`relative = recommended return − benchmark return`。詳細は [`../reference/data-sources.md`](../reference/data-sources.md) §Benchmark proxy。
- eval cap: cache 済み最新足 `2026-06-05`。target がこれを超える horizon は unresolved（集計から除外、`count` に反映）。
- macro context: replay は **macro-agnostic（macro_context=None）**。non-stale macro context が 3 週分しか無く、replay 用に過去 context を捏造するのは事実分離原則に反するため。macro context は hard gate ではなく soft diagnostic なので、profile 選定機構の比較には影響しない。

## サンプルの制約（重要）

- **4 週（2026-05-01 / 05-08 / 05-15 / 05-29）を用いた評価**。hold-out は 2026-05-29（最終 1 週）。
- 2026-05-22 は EDINET metrics スナップショット・JPX regulation スナップショットが DB に存在しないため skip。当日の状態は事後では取得不可。
- April 以前の週（04-10〜04-24）も EDINET / JPX がないため skip。
- eval cap が `2026-06-05` のため horizon 別の利用可能週数に上限がある。
  - 4w 解決済み: 2026-05-01（+4w=05-29✓）、2026-05-08（+4w=06-05✓）
  - 4w 未解決: 2026-05-15（+4w=06-12 > eval cap）、2026-05-29（+4w=06-26 > eval cap）
  - 8w: 全週未解決（+8w が eval cap を超える）

## 観察

### 4w 相対リターン（2 週の tuning サンプル）

- **4w relative は全 profile・両週で一貫して負（-5.6〜-12.3pt）**。recommended queue は上昇相場で benchmark に劣後。`#194` / 2026-05 retro の「売られすぎ × 割安 tilt が broad rally で構造的に劣後する」所見と整合する。
- 4w の profile 間優劣は週で反転: 05-01 では balanced（+0.96%）が strict（-0.88%）を上回るが、05-08 では balanced（-4.87%）が最下位。2 週では特定 profile が優越するという evidence は得られない。

### 1w 相対リターン（3 週の tuning + 1 週 hold-out）

- 05-15 の **balanced が 1w +6.07%（+3.07pt）** を記録。他週・他 profile と対照的。05-15 週は市場回復局面と推定され、バリュー系 profile が一時的に有利に働いた可能性がある。ただし 1 week は noise が大きく、この 1 点から「balanced が有効」とは結論できない。
- 05-29 hold-out: 全 profile が 1w で -0.53〜-2.60%（relative -1.1〜-3.2pt）。absolute も relative も小幅負。市場横ばいで overperform しなかった。

### Profile 設計上の懸念

- `fast_dislocation_count` は profile の緩さに強く依存（strict 9-33 / balanced 37-50 / loose 130-168）。`loose` は fast 候補を量産しており、推薦の質より量に依存するリスクは継続的に見られる。
- relative が 1 週間で最大 6pt 以上変動するため、1-2 週の評価では profile の優劣を判定できない。

## 判断

- **`balanced` を継続採用（据え置き）**。4 週・1w/4w 評価では特定 profile が一貫して優位という根拠は無い。
- 4w relative の一貫した負（oversold tilt の構造的劣後）は確認できたが、profile 閾値の問題か market regime の問題かを切り分けるには複数 regime にまたがる 6-8 週が要る。
- **次アクション**:
  - 2026-05-22 と April 週の EDINET/JPX データが取得できたら candidates 生成して本評価を追補する。
  - 8w が解決する 2026-07 末頃に本評価を更新する（05-01 の 8w は 2026-06-26、05-08 の 8w は 2026-07-03）。

## 再現

```bash
# 1. 各週の candidates を生成
#    05-01 / 05-08 は records/04-candidates からコピー済み
cp records/04-candidates/2026/05/2026-05-01.yaml .cache/replay/candidates/2026/05/
cp records/04-candidates/2026/05/2026-05-08.yaml .cache/replay/candidates/2026/05/

#    05-15 / 05-29: earnings calendar は allow-stale-jpx で過去日付の stale を許容
for W in 2026-05-15 2026-05-29; do
  uv run baibai-loop-screening run --asof "$W" --allow-stale-jpx \
    --output-path ".cache/replay/candidates/${W:0:4}/${W:5:2}/$W.yaml" --force
done

# 2. replay 評価
uv run baibai-loop-ledger screening-replay \
  --candidates-root .cache/replay/candidates \
  --profiles strict,balanced,loose --holdout-weeks 1 \
  --out docs/screening/replay-2026-05.yaml
```
