# Screening profile replay 評価 (2026-05 interim)

`#157` の screening replay / hold-out / forward return 評価。`strict` / `balanced` / `loose` profile を週次 candidates に replay し、各 profile の recommended queue の forward return を日経225 ETF proxy 比で比較する。再実行手順は [`../operations/screening-runbook.md`](../operations/screening-runbook.md) §Multi-week replay。

## 算出方法と価格基準

- ツール: `baibai-loop-ledger screening-replay`（`forward_return` + `screening_replay` モジュール）。
- forward horizon: asof + 1w / 4w / 8w（暦週、`asof + weeks*7` 日を on/before で解決）。
- 価格基準: J-Quants 日足を `resolve_price_on_or_before` で解決（adjusted close 優先、無ければ close_unadjusted）。entry / forward / benchmark を同一 basis に揃える。
- benchmark: 日経平均は J-Quants 未収録のため ETF proxy `1321`（野村 日経225 ETF）。`relative = recommended return − benchmark return`。詳細は [`../reference/data-sources.md`](../reference/data-sources.md) §Benchmark proxy。
- eval cap: cache 済み最新足 `2026-06-05`。target がこれを超える horizon は unresolved（集計から除外、`count` に反映）。
- macro context: replay は **macro-agnostic（macro_context=None）**。non-stale macro context が 3 週分しか無く、replay 用に過去 context を捏造するのは事実分離原則に反するため。macro context は hard gate ではなく soft diagnostic なので、profile 選定機構の比較には影響しない。

## サンプルの制約（重要）

- **現時点で replay できたのは 2 週（2026-05-01 / 2026-05-08）のみ**。`#157` が要求する 6-8 週には届いていない。
- 残り 6 週（04-10〜05-29 のうち未生成週）の candidates 生成は、各週 `bootstrap-cache` + `extract-edinet-metrics` が必要だが、**2026-06-06 時点で J-Quants の rate budget が枯渇しており、1 週あたり 10 分の timeout でも bootstrap が完了しなかった**（429 backoff）。rate budget 回復後に runbook 手順で生成し本評価を更新する。
- eval cap が `2026-06-05` のため、horizon 別の利用可能週数には上限がある。8w は asof ≤ 2026-04-10 の週のみ、4w は asof ≤ 2026-05-08 の週のみ。今回の 2 週はいずれも 8w が未到来で、評価は 1w / 4w に限られる。

## 結果（2026-05-01 / 2026-05-08、hold-out: 2026-05-08）

各 profile の recommended queue（5 銘柄）の forward return 平均と benchmark proxy 比 relative。

| 週 | profile | fast_dislocation | 1w 平均 | 1w relative | 4w 平均 | 4w relative |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 2026-05-01 | strict | 9 | -1.49% | -6.91pt | -0.88% | -12.26pt |
| 2026-05-01 | balanced | 37 | -0.43% | -5.84pt | +0.96% | -10.42pt |
| 2026-05-01 | loose | 130 | -0.61% | -6.03pt | +1.48% | -9.90pt |
| 2026-05-08 (hold-out) | strict | 16 | -4.00% | -1.98pt | -0.04% | -6.29pt |
| 2026-05-08 (hold-out) | balanced | 45 | +0.59% | +2.60pt | -4.87% | -11.12pt |
| 2026-05-08 (hold-out) | loose | 138 | -0.88% | +1.13pt | +0.67% | -5.58pt |

注: 8w は両週とも eval cap 未到来（count=0）のため省略。

## 観察

- **全 profile・全週で 4w relative が大きく負（-5.6〜-12.3pt）**。recommended queue は上昇相場で benchmark に一貫して劣後した。これは `#194` / 2026-05 retro の「売られすぎ × 割安 tilt が broad rally で構造的に劣後する」所見と整合する。
- **profile 間の優劣は週で反転する**。05-01 では balanced の 4w（+0.96%）が strict（-0.88%）を上回るが、hold-out の 05-08 では balanced の 4w（-4.87%）が 3 profile 中最下位。2 週では `balanced` が `strict` / `loose` に優越する根拠も劣後する根拠も得られない。
- `fast_dislocation_count` は profile の緩さに強く依存する（strict 9-16 / balanced 37-45 / loose 130-138）。`loose` は fast 候補を量産しており、recommended の質より量に寄る懸念は再確認できる。

## 判断

- **`balanced` を継続採用（据え置き）**。closed sample が 0 件、replay も 2 週のみで、profile を変更する evidence base が無い。2026-05 retro の据え置き判断を踏襲する。
- 閾値・tilt の変更は本評価では行わない。broad rally での oversold tilt 劣後という構造的傾向は確認できたが、profile 閾値の問題か market regime の問題かを切り分けるには 6-8 週・複数 regime の forward return が要る。
- **次アクション**: rate budget 回復後に 6-8 週を生成して本評価を更新する。hold-out（直近 1-2 週）を分離したまま、`balanced` の継続可否を再判断する。

## 再現

```bash
# 1. 各週の candidates を生成（rate budget 必要）
for W in 2026-04-10 2026-04-17 2026-04-24 2026-05-15 2026-05-22 2026-05-29; do
  uv run baibai-loop-screening bootstrap-cache --asof "$W"
  uv run baibai-loop-screening extract-edinet-metrics --asof "$W" --lookback-days 540
  uv run baibai-loop-screening run --asof "$W" --allow-stale-jpx \
    --output-path .cache/replay/candidates/${W:0:4}/${W:5:2}/$W.yaml --force
done
# 既存週は records からコピー
cp records/04-candidates/2026/05/2026-05-01.yaml .cache/replay/candidates/2026/05/
cp records/04-candidates/2026/05/2026-05-08.yaml .cache/replay/candidates/2026/05/

# 2. replay 評価
uv run baibai-loop-ledger screening-replay \
  --candidates-root .cache/replay/candidates \
  --profiles strict,balanced,loose --holdout-weeks 2 \
  --out .cache/replay/replay-payload.yaml
```
