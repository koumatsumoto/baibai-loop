# 用語集

採用する日本語名・英語名と意味の正本。責務と依存関係は[architecture](architecture.md)、投資・開発の採否は[doctrine](doctrine.md)、操作は各skillと[運用手順](../jobs/OPERATIONS.md)が所有する。ここへ算式・field・手順を複写しない。

## 情報と分析

| 日本語 | 英語 | このシステムでの意味 |
| --- | --- | --- |
| 情報収集 | Data Collection / L1 | 外部原本または明示したprovider-native表現と、その受領事実の保持。分析結果ではない。 |
| 機械分析 | Machine Analysis / L2 | 入力・規則・計算・基準時点から再現可能な観測、モデル、候補抽出。投資の採否を確定しない。 |
| 共通観測 | Observations | 原本から投影・正規化した分析材料。価格日、会計期間、株式basis、訂正等の意味を保持する。L1原本の代用品ではない。 |
| 解析モデル | Analysis Model | 特定の分析観点に応じた計算と結果の単位。機械学習modelだけを意味せず、モデル数を5に固定しない。 |
| シグナル | Signal | モデル等から得る判断材料。単独で売買判断や独立した一票にはならない。モデルと同義ではない。 |
| モデル生成 | Model Generation | 固定入力からモデルを計算し、生成結果を世代として保存すること。候補を選ぶこととは別。 |
| 候補抽出 | Screening | 保存されたモデルを明示した政策で読み、調査候補と抽出理由を得ること。買付採否ではない。 |
| 候補政策 | Screening Policy | どのモデルをどう用いて候補を選ぶかという機械規則。モデル追加だけで政策は変わらない。 |
| 生成世代 | Generation | 同じ固定入力に基づく対象・予定モデルと結果のまとまり。未生成と値の欠測は別で、各観測の日付が同一という意味ではない。 |
| 固定スナップショット | Snapshot | 入力または保存状態を固定したもの。全入力の過去時点再現を自動的に保証しない。 |

## 現在の解析モデル

| 日本語 | 英語 | 意味の境界 |
| --- | --- | --- |
| 企業財務 | Company Financials | 財務状態・収益力・利益や資本と株価の比較座標。L2の旧呼称Company Valuationを改める。将来の企業価値の最終見積りではない。 |
| 企業成長 | Company Growth | 保存された実績の状態・変化。将来成長が実現するとの判断ではない。 |
| 市場環境 | Market Context | 経済・市場・業種・個別の相対状態の機械観測。市場環境判断とは区別する。 |
| 外部評価 | External Assessment | 外部が提示する予想・rating・価値評価等の出所・対象期・比較条件と分析。提示された値を自分の判断に置き換えない。 |
| テクニカル分析 | Technical Analysis | 保存価格等の位置・勢い・変動幅などの機械観測。急落も複数ある観点の一つ。 |

**企業財務と企業価値は別の言葉である。** 企業価値の仮定付き評価は、将来の利益・現金創出・資本配分・リスク等を評価するL3の銘柄評価に属する。条件付きの式を決定的に計算しても、その仮定がL2の観測になるわけではない。

## 投資判断

| 日本語 | 英語 | 意味の境界 |
| --- | --- | --- |
| 投資判断 | Investment Judgment / L3 | 原典・機械観測・仮定を統合し、重要性・価値・リスクリワードを判断する領域。 |
| 企業調査 | Company Research | 企業の事業・財務・競争力・経営等を一次資料から調べること。 |
| 銘柄評価 | Stock Assessment | 個別銘柄の価値と支払価格、成立条件、見返りとリスクの評価。汎用名Assessmentだけで市場判断と混同させない。 |
| 独立検証 | Independent Review | 作者とは独立した根拠・仮定・算術・反証の検証。無リスク認定や人間の注文承認ではない。 |
| 売買提案 | Trade Proposal | 検証された評価を、価格・cash・保有状態へ適用した提案。約定とは別。 |
| 市場環境判断 | Market Assessment | 市場全体の条件・共通リスクとその意味を判断すること。L2のMarket Contextとは別。 |
| 調査対象の固定 | Selection | 対象・問い・必要入力を開始時に固定した記録。モデル生成、候補政策、人間の買付採否とは別。 |
| 判断作業の進行 | Operation | 固定対象からの作業・成果・再開の状態。完了が注文や約定を意味しない。 |

工程名の数に合わせてserviceや自律agentを作ることは意味しない。最終採否と証券注文はシステム外の人間が行う。

## 株式・資本・実行

| 日本語 | 英語 | 意味の境界 |
| --- | --- | --- |
| 株式の基本情報 | Stocks | 銘柄マスター・市場区分・業種・上場状態等。保有の有無に依存しない。 |
| 資産・運用の全体 | Portfolio | 確認済みの現金・取引・保有と運用成果を扱う領域。単一の保有状態より広い。 |
| 保有状態 | Position / Holdings | 個別銘柄の保有数量・取得原価等。Portfolioの一部であり、領域全体の名前には使わない。 |
| 取引台帳 | Ledger | 人間が確認した取引・資本移動等の記録。提案から未確認の約定を作らない。 |
| 運用成績 | Portfolio Performance / Outcome | 現金・未売却損益等も含む資産全体の成果。個別モデルの歴史評価とは別。 |
| ジョブ | Job | 一つの目的を持つ実行・成功失敗・再実行の単位。解析モデルと一対一ではない。 |
| ワークフロー | Workflow | 実行や工程の順序・依存・進行の組立て。情報層ではない。 |
| バッチ処理 | Batch Processing | まとまったデータを非対話で処理する方式。ジョブと同義ではない。 |
| スナップショット公開 | Snapshot Publication | 固定した保存物を公開すること。L1とL2を含み得る物理単位であり、L1そのものではない。 |

## 名称と保存契約

採用名称とPythonの配置、保存ID・DB table・JSON kind・R2 keyは別の契約。#1632のモジュール構成再設計では採用名称へ配置を揃えるが、既存履歴や参照を名前だけのために書き換えない。Company Financialsへの改名後も、明示的な保存契約移行を行わない限り保存model IDは`company_valuation`を維持する。

用語の変更を未実装の配置変更と混同しない。現行の実配置と移行状況はarchitectureと[実施Issue #1632](https://github.com/koumatsumoto/baibai-loop/issues/1632)を参照する。
