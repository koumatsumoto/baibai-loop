# Screening

保存済みの解析モデルから調査候補を抽出する。モデル生成は候補選定より先に完了し、候補外の企業もInvestment Judgmentから読める。候補政策は企業の経済的reject・価値評価・購入判断を代行しない。

<a id="rule-purpose"></a>
## 候補抽出の意味

通常政策は、収益力・事業拡大・営業回復・資本活用という経済経路ごとに、価格座標と事業座標を組み合わせる。一軸の極値だけで調査容量を使わず、かつ全経路の合格を要求しないため、経路内では二座標の順位の調和平均、企業間では最良の有効経路を使う。旧Y/YMは新しい通常候補を作らない。

順位は有限な注意配分のheuristicであり、期待収益・確率・健全性・買付順位ではない。相対上位は市場全体が割高でも生じる。業種内の異質性、少数参照群、有効経路数や座標相関による偏りも残る。二座標を独立した証拠票とは呼ばず、経路の数を加点しない。具体的な座標・期間・参照群・容量・同順位の扱いは[候補政策](../../engine/src/baibai_engine/machine_analysis/screening/policies/economic_paths.py)とその入力投影を正本とする。

欠測を0や一軸の満点へ置き換えず、その経路だけを未計算にする。成長・回復は現在の利益やCFの黒字を要求しない。四半期の悪化を欠測と扱ってannualの好値へ切り替えない。年次fallbackの順位もannual値を持つ母集団全体から作る。売上や営業改善を株式時価総額で割る座標は、負債込み事業価値の割安性を保証せず、追加投資・借換・希薄化はL3で評価する。

TTM不足時の完全FY経路は、CompanyGrowth v4以降が「対応期間未観測」と明示した場合だけ使う。金額の欠測・赤字・会計期間不一致をTTM不足へ読み替えない。最新FYを値の確認前に固定し、ownerが一年として構成した実測期間・連結範囲が揃い、直後の同じ会計暦の累計へ続く場合に限る。最新FYが短期決算・欠測でも古い好業績FYへ戻らず、部分期間を年率換算しない。

収益力はそのFYの親会社利益／現在時価総額と同FY営業利益率を使い、未確認利益をEPS×株数で作らない。直近四半期・報告で利益や営業利益率が非正なら、旧FYから収益力を復活させない。ただし正の収益力自体は成長の主張ではなく、横ばい・小幅減益だけでこの経路を除外しない。成長・回復は四半期優先と悪化・0による年次逃避禁止を維持する。新しいFY座標だけは、必要な各metricと比較相手のsource開示日がgenerationのas_of以下であることを要求する。事後訂正は文脈へ残すが、該当座標と順位母集団へ入れず、古い訂正前数値へ戻らない。既存の振り返り四半期・TTMの意味は変えず、完全な当時point-in-time再現も主張しない。FY経路の参照群にはTTMを採用した企業のFY観測も含める。カードは選択FY・経過日数・後続の直近報告／四半期を区別してL3へ渡す。資本経路は同FY簿価の出所・scopeの対応を現モデルで確定できないため、FY利益への切替えをしない。

資本経路の正の報告利益はこの経路の条件であり、赤字企業全体の除外条件ではない。利益/簿価は、保存PBRが含意する簿価に対する報告利益proxyである。簿価の個別source・会計scope・測定日は現モデルに未保存で、検証済み普通株ROE・平均自己資本利益率・資産解放額とは呼ばない。未実現資産の機会を全て拾う政策でもない。

<a id="candidate-discovery"></a>
## 調査への引渡し

機械E[r]/FV、四Approachの旧membership、保存市場判断、portfolioは新しい候補membership・順位を決めない。カードは原数値・符号・対象期・反対材料を保ち、Investment Judgmentは複数モデル・一次資料・必要な少数の候補外対照を比較し、価値獲得経路と反証を自ら評価する。旧run・旧Selectionは保存済みidentityと内容のまま読めるが、新しい標準経路へ混ぜない。旧runを新規生成するscreening run入口は撤去し、旧較正は当時のモデル契約を明示して別に扱う。

## 入力不足と品質

普通株masterから対象集合を固定する。価格日、財務対象期間・公表日、計算基準日、外部評価の取得時点を区別し、欠測・既知0・負値を保つ。取得coverageは成功した要求範囲で、全銘柄の入力充足ではない。全価格座標は共通の直近営業日の価格と有効な株式分母を使う。利益が欠測でも価格自体が有効なら成長や回復に使える。古い価格・利益・時価総額は観測日付きで保持する。各モデルの不足はその材料の不足として示し、候補数を満たすために別値で埋めない。

共通統合は非営業日も経済・外部評価を更新できる。as_ofが新しくても株価観測日を当日へ書き換えず、保存原本からの再計算を完全な当時point-in-time再現とは扱わない。EDINETの原本取得・offline抽出・訂正状態はsource統合で扱い、L3が必要な一次資料とCF/BSを追加確認する。

## 保存と読取

ModelGenerationは入力identity・計算revision・モデルを一組として保存する。ScreeningSelectionは別identityで、元generation・対象母集団・政策・結果を保存する。既存identityへの別内容の上書きは拒否し、再送で初回の公開時刻を変更しない。候補0件も正常な公開結果であり、過去の非空候補へ戻さない。

既定読取はresearch日以下の基準日を優先し、同日は公開時刻で選ぶ。generation評価時刻と候補公開時刻の両方がknown_at以下でなければならない。explicitの未知・未来identityをlatestへ差し替えない。Selectionは必要なモデル断面と政策結果をapplication DBへ複写し、再開は保存入力だけを読む。日次の再生成cacheは最近の公開政策に必要な世代と今回の明示生成を優先して有限に保持する。保持数・順序は[所有実装](../../jobs/src/baibai_jobs/maintenance/model_cache.py)を見る。削除は同じreleaseの公開成功後に限り、保存済み評価・提案・台帳・原本・較正とは別である。

取得・retry・受領反映・発行順は[OPERATIONS](../../jobs/OPERATIONS.md)が所有する。意味を変えない配置変更だけで計算revisionを更新しない。新規候補政策は`best-economic-path-v2`を使い、v1は保存結果の読取だけを残す。旧成長v3の欠測理由から期間statusを推定せず、完全FY経路を利用するには新世代の通常生成が必要である。既存世代・Selectionのidentity・hash・再開入力は書き換えない。
