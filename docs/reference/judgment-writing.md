# 判断文書の編集

文章の編集では、確定した数値・日付・単位・比較基準・source・支持と反証・判断の確度を変えない。本文にあった未確認や適用範囲の限定を、title・summary・下流の含意で落とさない。

語順や構成を整理しても、source→個社への伝達→Base/Downside→反証→代替案との比較を切り離さない。新しい根拠・因果・評価の採用が必要になったら判断内容を確定する工程へ戻り、変更した判断とその下流をreviewする。構造validationの成功を意味保全の代わりにしない。

同じマクロ説明や注意書きをcase・Base/Downside・所見へ複写して、情報が統合されたことにしない。重要な材料は、確認した観測と個社への経路、採用した仮定または変更しなかった理由を辿れる箇所にまとめ、他の欄はその判断に必要な差分だけを書く。数値へ反映した場合はどの利益・倍率・要求率・期間の前提に効いたかを示し、影響額を裏付けられない場合は方向や反証条件に留める。説明を揃えるために感応度や因果を捏造しない。

観測・導出・見積り・判断の定義は[doctrine](../doctrine.md#fact-analysis-separation)、field固有の意味と発行手順は対象reference・skillが所有する。
