# Stock Assessment

企業の事業理解・価値・反証を独立Reviewと一組で保存する。企業評価は現在cashや注文から独立し、行動と具体条件は[Investment Proposal](investment-proposal.md)、取引事実は[Portfolio Ledger](portfolio-ledger.md)が所有する。作業順は[Research skill](../../.agents/skills/research/SKILL.md)。型と保存条件は`research/assessment.py`・`assessment_store.py`が正本である。

## 観測と根拠

必要な入力・出典をsnapshotへ固定し、元runの存続を要求しない。機械ER/FVを企業評価へ重複転記しない。市場価格は未調整1株basisを明示する。財務factの対象期間末日と資料の公表・提出日、会社予想の対象期と公表時点を分ける。日次終値へ架空の観測時刻を付けず、後発資料を判断前の事実にしない。

一次性と企業からの独立性は別である。企業が作成してEDINET・TDnet・JPXから配布した資料もissuer-primaryであり、hostを理由に独立sourceへ数えない。転載・sponsor調査・同じpress kitは同じ原典familyとして扱う。顧客・partner・競合の資料も、その主体が直接観測・管理する事実の範囲だけを支持する。

過去財務や自社KPIの公表値は原典から確認できるが、将来計画の実現性や因果は別の主張である。採否を変える需要・競争優位・外部状態・pipeline成功の主張には独立した裏取りを求める。全記述へ機械的に2 sourceを要求せず、会社計画を下げるだけで独立見積りとしない。単一顧客の事例を市場全体へ一般化せず、非開示や検索不発を不存在の証明にしない。

裏取り不能や矛盾は影響と試したsourceを残し、重要な肯定的主張を無条件にBaseへ入れない。確認済み事業だけで合理的な幅を評価できることと、元の成長仮説を確認できたことは別である。重要な事実不足と将来の合理的な幅を分け、同じ原典の反復で答えが増えなければ再評価条件を残す。仮定次第で採否が反転すること自体を保留理由にせず、取得できる情報で幅を狭められるかと調査価値を問う。調べても確定しない将来条件は合理的な幅を残して判断し、全scenarioでの購入成立を要求しない。反転点は作者の条件下の必要値で、市場の実際の期待を観測した値ではない。利益・再投資・必要資本・分配が同時に成立する経路と照合する。

## 経済性から問いを選ぶ

Approachは「なぜ安く見えるか」の入口であり、企業がどう稼ぎ誰にcashが残るかの分類とは別である。結論を左右する経路だけを選び、複合事業の重要な経路を接続する。全問を埋めるchecklistや新しい分類fieldは作らない。

| 経済性 | 価値を左右する問い |
| --- | --- |
| 継続契約software/data | 更新・解約、seat/usage・単価、粗利と獲得・導入・hosting費用の回収。ARR・受注残・契約負債を区別し、未開示NRR/CACを創作しない |
| 人員依存project | risk負担、単価・稼働率・賃上げ・採用育成、検収・回収、不採算案件。受注や採用を同marginの即時売上にしない |
| IP・有限寿命の権利 | 既存収益の減衰、権利期間、更新/代替投資と撤退費、stageと成功の違い。償却の足し戻しで経済寿命を延ばさない |
| 市況・加工業 | 数量/価格/mix、在庫とヘッジの表示位置・期間、運転資金、維持/成長投資と稼働率。反転時は利益と資金を一緒に動かす |
| 資産保有・複合企業 | 連結scope、親持分・他の請求権、資金拘束、税・換金費用、分配の主体と時期。連結資産や預り資金を株主余剰へ変換しない |
| 金融仲介 | 再価格化、調達費・信用費用・OCI、普通株主資本と規制資本、留保後の終期ROE。金利方向だけで受益認定しない |
| 売却・回復 | 売却益と入金、税・返済・残存事業、回復期間と追加資本。一時利益を除いても、一回限りの資本改善まで消さない |

四Approachに対しては、現在利益の反復性、3FY平均が循環を代表するか、資産の帰属と回収可能性、再投資の追加支出と限界収益を問う。過去のcapital proxyや会社ROIC目標を新規投資の限界収益率としない。KPIの期間・分母・定義変更とM&A影響を揃える。

<a id="analysis-domain-integration"></a>
## 五領域の統合

Valuation（企業価値）は事業・資本が生む価値、Company Growth（企業成長）はその状態へ至る実績・採算の経路、Market Contextは環境の水準・変化から個社への伝達、External Assessmentは自己仮定との相違、Technical Analysisは保存価格の位置・勢い・変動幅を問う。個社の価格と事業の重要な不一致から必要なモデルへ往復する。重要な支持・相反・不足を既存の所見・仮説・最強反証へ接続し、固定のマクロ起点や全指標のコメント・支持票数を要求しない。

企業成長は[保存された実績状態・変化](company-growth.md)から問いを具体化する。累計・単独四半期・年間/TTM・期末残高を区別し、取得済み最新版による事後の振り返りを当時判断へ転用しない。年間の収益水準と直近同四半期の変化を併読し、前年や2年前を無条件に正常値としない。連続回復を主張する時は該当履歴を開く。一時利益が複数TTMに残ることを複数回の持続成長確認とせず、Q1の差とTTMの直前FY比を独立した変化に数えない。報告増加を有機成長と認定せず、営業CFの低下だけで正常FCF悪化や評価不能にしない。同じ利益を利益増・EPS増・低PER・外部目標の独立した支持票へ加算しない。補助機能の未提供と科目欠測を区別し、不足だけで企業価値・一次資料の調査を止めない。

マクロは需要・費用・資金だけでなく要求収益・織込み・流動性へも作用し得る。基準価値と独自の環境仮説を区別し、同じリスクを利益・倍率・要求率へ重複控除しない。外部値は元評価者、対象期、単位・株式basis、更新時点が揃う範囲だけ比較する。一致も不一致も元の仮定へ戻して検討し、転載数を独立票にしない。同年度・同定義の総額予想から最新累計実績を引く比較は達成に必要な残額で、実現確率や予想者の最新判断ではない。取得/更新日だけで全構成予想が最新決算を反映したとせず、株式basisの不足を総額比較の一律禁止へ広げない。

Technicalの時点・価格basis・実効履歴を確認し、価値実現期間と混ぜない。MA・BB・RSI・騰落率は同じ価格の加工で、独立した賛成票ではない。同じ窓の市場・業種相対を値動きの説明への反証に使い、単純差をalphaや原因の同定としない。価格局面だけで企業価値・Pmax・売買gateを変えず、他の根拠とどう結び付くかを説明する。欠測で他領域を一律停止せず、旧snapshotへ後付け再計算しない。

<a id="scenario-arithmetic"></a>
## 条件付き価値

resolved valuationは原価格、比較期間、案件ごとの[要求年率](../doctrine.md#required-return-policy)、Base/Downsideを持つ。計算可能なだけでresolvedにせず、重要な利益・資本・終価の根拠が未確認の例示は所見へ分ける。unresolvedでは理由を残し、価格・期間・Projectionをゼロや推定で埋めない。supportedは購入採用ではなく、Pmax超過・cash不足で企業評価をunsupportedへ変えない。

terminalは分配後に残る価値、cashは比較期間の累積分配。同じ起点の未調整1株へ揃える。配当・資産売却・買戻しを二重算入せず、終期の権利落ち後価格と未入金配当権利を分ける。権利確定前の未公表配当は仮定とし、公表済みだけの条件と混ぜない。

純粋算術は[valuation/scenario.py](../../engine/src/baibai_engine/valuation/scenario.py)が所有する。年率は条件付き・投資家の税費用控除前・分配再投資なしで、確率加重期待値やIRRではない。企業利益に含めた税・営業費用を除く意味ではない。計算・判定の精度を表示丸めへ合わせない。

<a id="valuation-model-choice"></a>
### modelと期間

株価比較より先に価値獲得経路と根拠から選ぶ。EPS×PERと12か月を自動採用せず、全方式を平均したり最高値を選んだりしない。

- 持続収益は価格・数量・費用から反復可能な利益/cashを置き、倍率に含む成長・再投資と別認識する資産を区別する。
- 回復・再投資は追加支出、運転資金、損失期間を含む。既に費用化した人材・研究開発を再控除しない。
- 有限寿命・資本解放は残存収益/回収資産、更新・撤退費、税、債権者や他の出資者の帰属と分配時期を扱う。

倍率据置でも、留保で簿価が増えるPBR一定とPER一定は異なる。終期の利益・簿価・分配を揃え、会社計画の残り必要利益を達成可能性の証明にしない。倍率上昇の事業根拠と、上昇しない反対条件も確認する。全変数を無関係に最悪化するだけでDownsideを作らない。

複数年では主要な中間年の事業・投資・資金と終期を既存calculationへ記す。期間を伸ばして分配だけ増やさず、利益・調達・残余価値も更新する。早期分配の時期が採否を変えるなら感応度で扱い、既存年率の意味を変えない。競合仮説で結論が反転するなら、何が確認されればmodelを変えるかを残す。

<a id="capital-bridge"></a>
### CFと終期資本

留保CFが重要なら期首・期末cash、非営業資産、負債、非支配請求、営業CF・投資・運転資金・分配・返済・増資と終期株数を同じ期間・単位で橋渡しする。差引済みの税・利息・投資を再控除しない。

営業EVに必要操業cashを含む場合は、別認識するcashからその必要額だけを控除する。不足をmax(0, ...)で消さない。NI×PERで株主価値を出した時に全現金を足したり負債を再控除したりしない。元本返済はcashとdebtの双方を減らし、株主価値から再控除しない。

分配停止なら残るcash、買戻しならcashと株数、増資なら調達額と分母を動かす。新規払込を既存株主の価値創出にせず、発行/転換の時期と配当権利に合わせ起点1株へ換算する。未コミットM&Aを実行済みにせず、織り込む時は対価・調達と取得価値の両側を扱う。

通常賃借料とリース負債を二重控除せず、会計基準変更を成長としない。非現金費用の足し戻しは経済消耗の不存在を意味せず、営業CFに反映済みなら重ねない。金融機関のgeneric cash-debtは余剰株主資産ではなく、規制資本・普通株主資本・OCI・分配可能性を区別する。

<a id="draft-calculation"></a>
### 計算資料

`research calculate <INPUTS>`を作者とReviewがそれぞれの確認入力で使える。typed ratioとProjectionの算術であり、文章を解釈したり売上・利益率からterminalを作ったりしない。同じ誤ったterminalを入力すれば一致するため、原資料と上流算式の独立確認が必要である。

`research calculate --cash-share-cb <INPUTS>`は、額面現金と転換価値超過分の株式交付を持つCBだけの別の条件付き試算。額面は既計上債務の消滅に対応し、株主価値から再控除しない。決済VWAP、配当調整用参照終値、評価株価は別入力。端株の現金精算をVWAPと等しいと置く試算と、VWAPを終期株価へ結ぶ固定点を区別する。契約の調整時期・対象本数・権利は原典で確認し、連続近似や整数固定点の不存在を実決済へ読み替えない。Assessmentや注文の採否は別判断である。

<a id="valuation-context"></a>
### 原価格の成立条件

assessment-evaluateのvaluation_contextは原価格・原期間・原要求率の読取資料。Pmaxの代数的な読み替えであり、独立した割安signalや市場予想ではない。Downsideの不足を追加購入gateにしない。

固定terminal/cashのh+12感応度は総価値・総returnを変えず、年率損失の絶対値が縮んでも損失は減らない。経済的遅延では利益・分配・返済・資金・希薄化が変わる。materialならcalculationとcountercaseで条件を組み直し、表示だけで遅延検証済みとしない。

<a id="permanent-loss-axes"></a>
## 永久損失

資金余力、返済、CF、希薄化、顧客集中、構造的衰退、governance/accountingの7軸を調べる。確認済みの曝露は、大きさや確率が未確定でもunknownへ戻さない。verifiedは記した根拠を確認した範囲であり、リスク不存在や将来の安全性を保証しない。赤字や下方修正だけで永久損失とせず、重要な根拠不足を小口購入やoverrideで通さない。

<a id="independent-second-pass"></a>
## 独立Reviewと保存

作者とは別の作業者が原典、年度見出し・当期/前期列、単位・期間、仮定と最強反証を確認する。resolvedではBase/Downsideのterminalとcashを独立入力から再計算する。作者の抽出値・入力・出力のコピーやhash一致は独立性・真実性の証明ではない。unresolvedでは数値検算を捏造せず、所見・不足・結論を独立に検討する。

資本bridgeは留保・投資・分配・返済・希薄化の両側を追う。外部一致や価格情報の多重票を割安確認へ変換せず、重要な相反と比較不能な条件を検討する。非重要なunknownを許容する根拠と、読み直した範囲・限界をReviewへ残す。重要な未確認が残ればsupportedへ進めない。

評価とReviewはexact coreへの一組で保存する。最新を選んでから検証し、unsupported/unresolvedを理由に古いsupportedへ戻らない。提案はAssessment ID・core hash・Review IDへ束縛する。保存読取へ現在のcashや価格条件を適用しない。

<a id="assessment-refresh"></a>
## 差分refreshと文章編集

同日評価は同じpairを提案へ使える。翌日以降の当日算術は差分draftで価値・開示・仮説・株式単位・残る期間・今後分配を確認し、新しい独立Reviewへ束縛する。素材にしたpriorと最新のsupersedes先は別で、元source/factの日付は保つ。全資料の毎回再取得を要求しない。

旧12か月を日々延長せず、受取済み分配や、今売っても受け取れる確定権利を今後分へ再算入しない。整数月の比較窓を厳密な残日数と同一視しない。古い評価の原価格算術は現在projectionが使えなくても閲覧できる。

編集では確定した数値・単位・日付・比較基準・支持/反証・不確実性を保ち、titleやsummaryで限定を落とさない。同じ説明を各欄へ複写せず、重要な材料から個社仮定・比較理由まで辿れるようにする。新しい根拠・因果・評価を採用したら判断工程へ戻り、変更部分と下流を再Reviewする。
