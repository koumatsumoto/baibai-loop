# Trade Proposal

[exact評価pair](stock-assessment.md#independent-second-pass)を確認済み価格・cash・保有/注文へ適用する。未評価の重要材料は評価/Reviewへ戻す。公開と採用/予約/注文/約定は別で、操作は[skill](../../.agents/skills/investment-judgment/SKILL.md)へ。

## 行動と比較

| 行動 | 意味 |
| --- | --- |
| buy | 作者の上限で買う指値提案。単なる監視価格ではない。 |
| hold | [確認済みの保有継続](#holding)。 |
| sell | [確認済み理由による全量回収](#holding)。 |
| no_action | 完成した経済比較による見送り。 |
| defer | 調査・入力・判断条件の不足。 |

固定Operation全対象をnew/holding別に被覆する。未調査はunfinishedの理由/参照に対応する評価参照なしdefer、Review済みuncertain/unresolvedは参照付きdeferにできる。0対象に空提案は作らない。

結論が`uncertain`の評価から新規`no_action`は発行しない。条件不足の保留を経済的見送りにせず、`defer`と再確認条件を残す。一方、理由付きで不利と結論した`unsupported`は数値価値が未算定でも見送れ、`supported`も価格・代替比較で見送れる。不明点の全解消を要求する規則ではない。

<a id="report-summary"></a>
## 人間向けの要点

`headline`と各項目の`rationale`は、最初に読む2〜3文で結論・主な理由・採否を左右する重要な留保/価格条件をまとめる。詳しい比較・根拠は対応する本文や評価へ置くが、重要な否定・未確定・条件を詳細だけへ追いやらない。Webの短い表示を目的に条件付き判断を無条件の推奨へ変えない。

これは作者の記述指針であり文数の検証gateではない。既存保存本文は先頭に結論がある保証がないため自動切出ししない。要約変更も内容変更として[Review・保存](#publication-review)を行い、旧提案の本文やhashを上書きしない。

保存レポートは評価作者の最強反証とReviewerの反論を別に示し、価値実現の経路・時期の判断/根拠・遅延リスクも元の評価から引き継ぐ。比較期間を実現時期へ、保存仮説を実現確約へ読み替えない。旧表示データの未収録は反証/リスクなしでなく、原評価の再採択や採否変更を伴わない。

価値の各ケースも、その仮定に作者が引用した資料と当時の時計を別々にたどれるようにする。同じ資料の再引用を独立票にせず、資料の事実と作者の将来仮定を区別する。旧表示の引用未収録を根拠なしや確認済みへ読み替えず、別ケースや現在の資料で補わない。投資理由の説明・状態・反証条件にも、その区画の保存引用を別に示し、各文の支持や当初理由を現在の資料で補作しない。

## 条件付き購入

quoteは未調整終値で売気配ではない。評価/権利basisとcashを確認し、作者limit・実約定と分ける。許容価格域の説明は任意で、架空quoteや追加gateを作らない。

`place_limit`は[上限以下で買う指値](https://www.jpx.co.jp/glossary/sa/174.html)。quote超も可能だがstop/自動上乗せではなく、上限支払やquote近辺の約定を保証しない。価格分類は[提案契約](../../engine/src/baibai_engine/investment_judgment/trade_proposal/contracts.py)、呼値は[grid owner](../../engine/src/baibai_engine/portfolio/holdings/price_grid.py)が持つ。

PmaxはBase・期間・[要求率](../doctrine.md#required-return-policy)からの上限で、期待値/勝率/最適指値ではない。上振れでlimitのBase年率未達を通さない。quoteがPmax超でも低いlimitで待てるが、判断未了の監視はbuyにしない。

[受容理由](stock-assessment.md#uncertainty-and-decision)のあるsupported/resolvedを使う。[no-add](../doctrine.md#investment-strategy)を守り、active買予約への追加や約定済み提案の全売却後再利用もしない。

<a id="limit-selection"></a>
### 指値と待機案の選択

指値・数量・待機案を[経済比較](../doctrine.md#economic-return-policy)する。cash/単元・既知イベントで判断が変わる少数案を現金維持/他案と比べ、採用理由・重要差・反転条件を残す。全呼値探索や件数ノルマは不要。同じBase年率でも倍率上昇/利益回復への依存は異なり、Pmax内だけで採用しない。

[同context](../../engine/src/baibai_engine/investment_judgment/trade_proposal/inputs.py)と購入算術を使い、鮮度は実quote、支出/利回りは作者limit、価格/株数basisはsnapshotへ揃える。入力変更時は比較を取り直す。

contextの市場判断はOperationのSelectionに固定した当時の投影で、反証・不確実性・個社への伝達条件をcash/待機案と併読する。現在の判断への差替えや鮮度の再認定はせず、未保存や旧投影の未記録時計を補わない。重要な後発情報や未評価の個社影響は評価/Reviewへ戻し、市場判断の存在だけで価格条件や採否を変えない。

最終contextでは同Operationに固定した選定理由・最初の問い・主要リスクも、当時の情報締切とSelection hash付きで併読する。選定の仮説であって現在の反証・回答・採否ではなく、後の評価で何が変わったかを比較する補助である。未回答を自動的に不利/見送りへ変換せず、旧Selectionや提案を新しい問いで書き換えない。

最終contextの固定L2環境は、選択時の外部評価・市場/世界/産業を反証の再訪用に限定表示する。表示省略と未生成・結果内欠測を分け、元の出典/対象期/比較不可/coverageを保持する。外部目標値の複数表示を独立の支持票とせず、共有の抽出待ちを影響なしとしない。現在の採択・因果・価格条件へ自動昇格せず、旧Selectionにない入力は補完しない。

context/check/previewの指値試算は計算条件の上限と実quoteを分ける。観測日・価格basisは実quoteに属し、指値やPmaxへ付け替えない。contextの自動候補試算は作者による採択済み指値ではない。

価格ごとの試算には、終期価値・累積分配を据え置く既存の遅延感応度も示す。元評価株価の結果を指値へ転用せず、期間延長を採択した評価・遅延予測・保有期限や新しい採否gateにしない。損失ケースの年率が0へ近づいても損失額が減るわけではなく、資金拘束、遅延で変わる価値/分配・費用は別に検討する。

[資本方針](../doctrine.md#required-return-policy)に従い、小口・上限量・現金維持の損益金額/残cashを比較する。同じ一株returnでも集中・ADV・no-addの放棄利益は異なる。

context/check/previewは同じ未拘束cashで指値全量成立する条件例で、数量未指定の上限量は採用量でない。[分配/税費用の算術](stock-assessment.md#scenario-arithmetic)に従い残cash/現金維持は無利息。全体NAV/約定予測ではなく、待機後の買付・cash利回り・費用が採否を変えるなら同一終期の別案へ反映する。

保存提案の表示でも、同日起点の確定評価・指値・選択数量が揃う場合だけ、この算術でBase/Downsideの損益金額と残cash・現金維持を比べる。各銘柄だけが指値全量で成立する条件で、他の買付や既保有を合わせたNAVではない。元の評価株価の年率は別表示し、現在入力での再判断や旧判断の採用し直しはしない。旧表示JSONの未収録、数量/価値/起点不足を0や上限数量で補わない。

数量上限は売買代金だけから求め、買付費用を自動確保しない。既知の買付費用があれば、その支払い後も未拘束cash内に収まる数量を選ぶ。比較には確認できた費用と仮定、不明なspread/impactを分けて残し、費用の未算入を0円確認としない。

ADVの平均と同じ窓の中央値・有効観測数を併読し、一日の急増を通常の売買規模としない。窓は共通営業日数でなく実在価格barで、欠落日は無出来高0へ埋めない。窓情報を持たない旧モデルは不明のまま引き継ぐ。中央値も板の厚み・吸収可能量ではなく、警告や数量上限を変えない。

待機では逃す利益と保持cash・他機会・回避損失・追加情報を比較する。悪材料時の逆選択/event gapも考え、約定率×Base利益だけで選ばない。価値織込済みの毀損をpenaltyへ重ねず、機会損失を事後最高値としない。ADV/日足から板・queue・impact・精密約定率を創作せず、`low <= limit`も約定保証にしない。確率には[根拠・幅・感応度](../doctrine.md#fact-analysis-separation)を示す。

session・前提/イベントと未約定・部分約定・新情報後の確認時点を残す。変更は[再Review](#publication-review)へ。部分約定後は実保有・残注文・cash/no-addで判断し、残数再提案・指値引上げ/延長・上限超追随を自動化しない。

<a id="price-grid"></a>
### 具体条件

価格・数量・session・前提を保存する。共通gridはJPX「その他」の保守案でTOPIX500最良呼値/注文受理を保証しない。分類/確認期間等のterms不足は経済判断と分け、limitを後日quoteで補わず価格/数量未確定を完成としない。

session/見直し時点はbroker期限でなく、実期限は人間確認の取引事実。[価格・時間優先と板寄せ/ザラバ](https://www.jpx.co.jp/equities/trading/domestic/04.html)で結果が変わり、即時約定も保証しない。

<a id="holding"></a>
## 保有継続と回収

当初理由をexact参照で読み、今回の重要な一次根拠で確認する。

- 重大なbreakはsellを優先。quote/valuation/数量basis不足はterms不足で、holdへ戻さない。
- intactは旧valuation/quote欠測でもhold可だが、当日の十分な見返りとは別。将来の幅だけで取消さない。
- 見返り十分/不足には同日起点valuationと現在算術が必要。仮説未評価はdefer。

保存表示で「十分な残存見返り」を確認したholdは、同日起点の確定評価・保存終値・数量basisが揃う場合だけ、その終値での保有機会費用を示す。元評価株価の年率、購入原価からの損益、売却可能価格と分け、旧表示や仮説維持だけのholdへ十分性を補作しない。現在quoteや後発評価へは差し替えない。

保存表示では判断対象の保有数量・株式単位の確認状態・原価と当時の入力/台帳時計を残す。未確認数量を注文可能量へ、旧表示の未収録を保有なしへ補わず、原価を今後の見返りの分母や売却下限にしない。

残存見返りは今後保有する増分。受取済みcash、今売っても得る確定済み未入金配当を再算入せず、旧horizonの割直しで水増ししない。税・費用・遅延・下振れが結論を変えるなら扱う。

sell limitは作者の一株回収下限。実quoteの上下とも可能だがgridに合わせ、黙って切り下げない。全量notionalは税費用前の回収下限で予想約定額/確定cashではない。下限回収・高値待ち・継続と未約定後の再確認を記す。

具体条件付きsellも、確認済み実quote×提案数量を保存ADVと比較して既存の流動性注意を示す。下限を下げて規模を小さく見せず、quote/数量basis/ADV不足は未評価とする。価格窓・中央値・有効本数と併読する参考規模で、約定可能量・回収日数・現在の板を表さず、売却判断や全量数量を自動変更しない。旧保存の注意は書換えず、現在previewの注意を分ける。

`remaining_reward` sellは実quoteでの不足に加え、同評価・期間・今後分配を作者下限で保有する機会費用（`sell_limit_projection`）も比べる。観測quote/売却後収益ではない。下限で保有が魅力的なら下限引上げ/hold/再確認と比較してなお回収する理由をReviewする。自動Pmin・Pmax sell gate・現在十分なのにTarget到達時だけ売る条件を作らず、broken sellには無効valuationの下限算術を課さない。保存表示でも、残存見返り不足の売却に同日起点の確定評価と下限が揃う場合だけ、同じ算術を保有継続との比較として示す。元評価株価や売却後の収益と分け、旧表示・条件不足・仮説不成立を0や保有推奨で補わない。

価格下落・期間経過・回復遅延・Target到達・新規購入条件未達・他候補/集中warning単独では売らず、次候補も必須にしない。全量sellの端株/不明数量は丸めない。active予約の注文処理を別確認し、人間報告を台帳反映してtermsを再確認する。

<a id="publication-review"></a>
## Review・保存・preview

別作業者の内容Reviewを正規checkの`draft_sha256`へ束縛し、valid/file hashで代用しない。内容変更は再Review、入力事実変更はsnapshotも取り直す。読取時刻差だけを事実変更にせず、検証は実時刻、公開はエンジンの初回発行時計を保つ。

提案のReviewは参照評価の独立Review完了以後に行う。評価pairの保存だけが遅れた場合は、内容の完成が遅れた場合と区別する。

公開時に固定scope・exact評価pair・現入力を照合する。previewは保存案と現在再試算を分け、旧保存を下限比較済みとせず、現在上限超でもlimit/数量を書換えない。利用不能を当時の誤りと即断せず、過去本文/hashへ現在条件を適用しない。

見送り・保留の参照評価が更新された場合も、現在previewは変更と最新評価IDを示す。旧評価の価値を現在の見送り算術へ使わず、新評価の採否・価格へ自動付替えもしない。評価参照のない未完deferは、後発評価の存在だけで完成へ進めない。

執筆contextでも、固定した評価が最新でなければ現在quoteの見返りを返さない。元pairと最新IDは比較材料として残し、新評価への束縛・採用を自動化しない。買付診断に残る旧上限等はblocker付き診断であり、現在使える条件ではない。

saved/current warningを分け、人間へ示す。既知factor比率が下限ならcoverageを示す。保有時価/NAVと取引は[Ledger](../../.agents/skills/ledger-record/SKILL.md)に従う。

## 提案の訂正と人間の報告

[非購入報告](../../engine/src/baibai_engine/investment_judgment/trade_proposal/record_contracts.py)はexact提案への別記録でno_actionではない。本人の言葉・報告/対象時点・要約を分け、未発注/取消/未約定/永久却下を推測せず、提案/Review/台帳を変えない。

誤記録はexact参照/理由付き追記訂正で最新候補から除く。残りは元の基準日・発行時刻・ID順で選び、関連旧提案の優先や訂正時刻の再順位付けをしない。原本/訂正はIDで読め、完了Operationは不変。誤記録と明示訂正した提案の現在previewは使用不可とし、現在算術へ再適用しない。元の保存行動/条件は残し、訂正先を自動適用せず、本人の非購入報告や後続提案の存在だけを誤記録としない。保存表示/previewは同じ訂正集合、人間報告は別表示とし、新推奨/適格性回復や当日refreshの代わりにしない。
