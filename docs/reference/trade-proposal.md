# Trade Proposal

日本株の正式提案で比べるのは、**この時点で、同じ元手を同じ期間にどう使うか**。[対象の評価と独立Review](stock-assessment.md#independent-second-pass)を土台に、採用する行動に必要な現在の条件を確かめる。割安の根拠があっても、現金や別案の方がよければ買いを提案しない。査読済みの評価がなければ理由付きで保留し、根拠を補わない。新しい重要材料があれば評価に戻す。提案の発行だけでは採用・予約・注文・約定にならない。採否と発注は人間が担い、取引結果は本人の報告に基づく[台帳](../../.agents/skills/ledger-record/SKILL.md)へ別に記録する。操作は[skill](../../.agents/skills/investment-judgment/SKILL.md)へ。

[固定入力](#fixed-context)は選定時の材料として読み、発行時に行動に応じて確認する価格・立会・未拘束cashなどと分ける。[購入](#limit-selection)・[保有継続/回収](#holding)の比較から[Review・保存](#publication-review)へ進む。

## 行動と比較

| 行動 | 意味 |
| --- | --- |
| buy | 作者の価格上限で買う方針。保存時の具体的な注文条件があるかを別に示す。 |
| hold | [確認済みの保有継続](#holding)。 |
| sell | [経済的な全量回収、または注文を伴わない全量/一部の資金配分案](#holding)。 |
| no_action | 完成した経済比較による見送り。 |
| defer | 調査・入力・判断条件の不足。 |

固定Operation全対象をnew/holding別に被覆する。未調査はunfinishedの理由/参照に対応する評価参照なしdefer、Review済みuncertain/unresolvedは参照付きdeferにできる。0対象に空提案は作らない。

事業の中核仮説が一次資料の独立Reviewで反証されたなら、数値価値や終値がなくても見送れる。事業に未解決があっても、査読した普通株の権利と観測終値・立会日・株式単位が今の比較と一致するなら、その価格に限った不支持を見送りの理由にできる。価格に依存する比較では、評価・資料を今日確認しても古い終値の鮮度は回復しない。別価格で再検討する条件は発注条件でない。

価格を支持した場合でも、同じ元手・期間で選んだ現金や別用途を作者が説明し、独立した提案Reviewで確かめて見送れる。事業の結論が未確定なら、価格支持の一次根拠が独立確認済みで、今の比較にも同じ価格・取得権が使える場合に限る。事業の結論が確定している通常の現金比較には新しい終値を要求しない。ただし評価に明示した期限付きの取得権は、見送りでも未確認や失効のまま使わない。

最終取得日の引け以降、または期限まで取引所の現物立会がないと分かる場合は、同じ権利を新たに取得できない。その後の立会日は不明でもよい。立会表の欠測や不明な区分を休場とみなさず、確認済みの連続区間から分かる下限だけを使う。買付条件の検査でも、保存した見送りの現在価格を再試算するときでも、失効と立会未確認は分ける。下限だけで取得できるとは判定せず、当時の見送りを取り消さない。比較が未完なら`defer`と再確認条件を残し、発注条件が不明なだけで経済的見送りにはしない。

[米国株の隔離MVP](us-research-mvp.md)の `no_action` は売買を判断しない固定表示で、日本株の正式な `no_action` や `defer` には当たらない。

<a id="report-summary"></a>
## 人間向けの要点

最初に、**いつのどの価格で、買い手に残る権利が割安だと言えるか**（支持・不支持・未確定）と、**資金の使い道として何を提案したか**を分けて伝える。同じ銘柄でも取得者や取得時点が違えば、受け取れるものが違う。見送りは割高の証明ではない。値段だけが変われば支持できる場合と、会社や権利の事実がまだ足りない場合を区別する。査読済み評価がない対象はその旨を示し、旧評価で価格判断が未記録なら、当時の行動・旧stance・機械上限から復元しない。

`headline`と各項目の`rationale`は、最初に読む2〜3文で結論・主な理由・採否を左右する重要な留保/価格条件をまとめる。詳しい比較・根拠は対応する本文や評価へ置くが、重要な否定・未確定・条件を詳細だけへ追いやらない。Webの短い表示を目的に条件付き判断を無条件の推奨へ変えない。

これは作者の記述指針であり文数の検証gateではない。既存保存本文は先頭に結論がある保証がないため自動切出ししない。要約変更も内容変更として[Review・保存](#publication-review)を行い、旧提案の本文やhashを上書きしない。

根拠は元評価の仮説・支持/反証/未確認・当時の出典をたどれるようにする。作者の見積りと査読者の反論、資料そのものと仮定、比較期間と実現時期は別である。資料の再引用を独立票にせず、未記録を「反証なし」「確認済み」に変えない。七観点や価格条件をどう表示するかは[Webの表示契約](../../web/README.md#提案レポートの読み方)を参照する。

<a id="fixed-context"></a>
## 固定入力の読み方

### 市場判断

contextの市場判断はOperationのSelectionに固定した当時の投影で、反証・不確実性・個社への伝達条件をcash/待機案と併読する。保存提案のWeb表示と振り返りも同じSelection hash/市場判断IDを照合し、固定投影を任意の当時資料として読む。旧欠欄や不読は中立・確認済みへ補わず、元提案の採否は変えない。現在の判断への差替えや鮮度の再認定はせず、未保存や旧投影の未記録時計を補わない。重要な後発情報や未評価の個社影響は評価/Reviewへ戻し、市場判断の存在だけで価格条件や採否を変えない。

公開時の選定原本を確認するときは[Caseの照会](screening-runtime.md#case-evidence)を使う。現在の運用Selectionや最新の市場本文を当時の原文の代用にしない。

### 元依頼・選定理由・探索時の観測

最終contextでは同Operationに固定した元依頼の全文・scopeと、選定理由・最初の問い・主要リスクを、当時の情報締切とSelection hash付きで併読する。元依頼の否定・比較条件を選定要約で置き換えず、後発指示や現在の操作許可を補作しない。選定理由は仮説であって現在の反証・回答・採否ではなく、後の評価で何が変わったかを比較する補助である。未回答を自動的に不利/見送りへ変換せず、旧Selectionや提案を新しい問いで書き換えない。

新規対象に過去の買付提案があれば、執筆時刻までに公開された同銘柄の直近の買い提案を比較する。前案の対象取引日・指値・数量は当時の条件で、約定や注文継続を示さない。具体条件なしの前案を古い具体案にすり替えず、作者上限と保存済みの経済結論を区別する。その後に保留・見送り案があれば、直近の買い案は直近の判断ではない。終値は日付・株式単位・価格基準を揃えて比べる。観測終値が同じでも作者の指値は変わり得る。価格・企業価値・待機の得失のどれが変わったか、変わらないなら今も同じ案を出す理由または見送る理由を記す。

「買わなかった」などの本人報告は、当時の提案**全体**について執筆時点までに受領した言葉である。発言・引用と文脈の要約、対象・発言・記録の時刻を分ける。記録のない理由を補わず、個別銘柄への恒久拒否、現在の保有・注文・現金へ読み替えない。初出・未読・当時まだ受領していないことも非購入を意味しない。訂正を知る前の時点に後から訂正を適用したり、訂正先を自動で採用したりしない。保有の元判断は[実際の買付報告との結びつき](#holding)を読む。

[探索時の観測](../../engine/src/baibai_engine/investment_judgment/trade_proposal/discovery_context.py)があれば、調査の入口にした手掛かりと、後に原典で支持・反証できた内容を比べる。現行索引からは対象の保存行を読み、明示した比較相手の行は対象と別に読む。対照を提案へ追加したり、該当する問いの数から推奨順を作ったりしない。旧方式の技術・財務の支持・不利はその時に記録された意味のまま扱う。該当行や当時の項目がなければ現在のモデルで埋めない。

### 年利益の観測差

企業財務は基準日までの開示、企業成長は固定release内で遡って読んだ各期の観測を使う。同じGenerationでも年間利益の版が異なり得る。調査対象の両観測は元期・基準・単位・出典/精度をそろえて読み、欠測や期間不一致を値差へ変換しない。同数値は独立確認や比較可能性の認定でなく、値差も訂正原因や採用すべき利益を確定しない。重要差は評価/Reviewへ戻し、保存した探索行・価値・価格を自動変更しない。

保存額は整数精度のまま併読し、比較用の浮動小数変換で丸めない。値を表示できても期間・基準まで読めたとは限らず、比較不能理由を残す。形式不明・非有限値を0利益へ補わない。

原モデルへの参照位置はその固定入力内だけで有効で、表示対象の並びや別Generationの位置を流用しない。

<a id="fixed-price-comparison"></a>
### 固定L2環境

最終contextでは、選定時に保存した外部評価・市場環境と、個社の12–1モメンタムを併読する。産業・社会のモデルは元のSelectionに含まれる場合だけ当時の観測として読み、現在の判断に効く記事は[必要時に原典を読む](stock-assessment.md#recent-news-research)。[個社TradingViewの外部評価](model-observations.md#tradingview)は新規の日次L2や通常の提案入力に含めず、必要時のL3調査に限る。12–1は直近約1か月を除く[調整後価格の端点比較](model-observations.md#technical-analysis)で、現在のquoteや配当込み収益ではない。保存された起点・終点・基準・欠測理由を保ち、他のテクニカルは同じSelectionの `full_result_ref` で読む。未生成、旧版にない欄、結果内欠測と表示省略を区別し、現在のモデルで補わない。外部目標値の転載を独立票とせず、共有の抽出待ちを影響なしとしない。

市場の倍率水準と地合い（指数の方向・上昇の広がり）を分ける。指数を上回っても自己騰落がマイナスなら株価自体は下落しており、同業にも劣後すれば個社固有の強さとは限らない。[同じ端点・調整基準と比較母集団](model-observations.md#relative-market-comparison)を確かめる。執筆用の `r20_index_sector_windows` は市場共通暦の指数比較と、個社の実在20barによる同業比較の**日付だけ**を照合する。端点一致は価格の存在や比較可能性の認定ではない。異なる窓は分けて記し、欠測を0にしない。代理指数で結論が変わる場合や12–1と直近が逆向きの場合は、都合の良い窓だけを採らない。決算等への反応と読むなら公表時刻が窓のどこにあるかを確かめ、引け後公表より前の値動きをその決算に帰属させない。

判断を変えるなら「需要・単価・借換などを通じて普通株に帰属する資金が変わる」のか、「価値は同じで現値・待機の得失が変わる」のかを、既存の `rationale`・`comparison`・`review_conditions` に記す。新しい重要仮定は評価と独立Reviewへ戻す。地合いが良いだけで倍率上昇をBaseにせず、逆風でも損失を織り込んで価格余地が残れば一律待機にしない。保有は新規買付の逆ではなく、[仮説の反証と残存見返り](#holding)を比べる。どちらの行動も変わらなければ、次に確かめる事実が変わったか、増分なしだったかでよい。

## 条件付き購入

quoteは未調整終値で売気配ではない。評価/権利basisとcashを確認し、作者limit・実約定と分ける。許容価格域の説明は任意で、架空quoteや追加gateを作らない。

`place_limit`は[上限以下で買う指値](https://www.jpx.co.jp/glossary/sa/174.html)。quote超も可能だがstop/自動上乗せではなく、上限支払やquote近辺の約定を保証しない。価格分類は[提案契約](../../engine/src/baibai_engine/investment_judgment/trade_proposal/contracts.py)、呼値は[grid owner](../../engine/src/baibai_engine/portfolio/holdings/price_grid.py)が持つ。

PmaxはBase・期間・[要求率](../doctrine.md#required-return-policy)からの上限で、期待値/勝率/最適指値ではない。「100円で支持」の記録から120円でも割安と推認しない。支持を確認できた参照価格までの指値を検討し、それより高い価格で買うなら、その価格を裏付ける新評価・Reviewを要する。元の割安判断が不支持でも、同じ権利・事業前提で値段だけが反転条件なら、査読された**明示額とPmaxの低い方**までを指値候補にできる。文章に金額が出ただけでは条件額とみなさない。未記録・未確定・明示価格なしの不支持は現在の買付数量・上限を生まず、必要な事実を改めて評価する。給付・特別配当等で取得できる最後の立会が価格判断を左右する場合、提案の対象立会とその最終日を照合する。同値でも期限後や期限不明なら新規買いには使えない。入金日や過去の議決権基準日で代用しない。上振れでlimitのBase年率未達を通さない。quoteがPmax超でも低いlimitで待てるが、判断未了の監視はbuyにしない。

[受容理由](stock-assessment.md#uncertainty-and-decision)のあるsupported/resolvedを使う。[no-add](../doctrine.md#investment-strategy)を守り、active買予約への追加や約定済み提案の全売却後再利用もしない。

<a id="limit-selection"></a>
### 指値と待機案の選択

指値・数量・待機案を[経済比較](../doctrine.md#economic-return-policy)する。cash/単元・既知イベントで判断が変わる少数案を現金維持/他案と比べ、採用理由・重要差・反転条件を残す。全呼値探索や件数ノルマは不要。同じBase年率でも倍率上昇/利益回復への依存は異なり、Pmax内だけで採用しない。

[同context](../../engine/src/baibai_engine/investment_judgment/trade_proposal/inputs.py)と購入算術を使い、鮮度は実quote、支出/利回りは作者limit、価格/株数basisはsnapshotへ揃える。入力変更時は比較を取り直す。

#### 価格と遅延

context/check/previewの指値試算は計算条件の上限と実quoteを分ける。観測日・価格basisは実quoteに属し、指値やPmaxへ付け替えない。contextの自動候補試算は作者による採択済み指値ではない。

価格ごとの試算には、終期価値・累積分配を据え置く既存の遅延感応度も示す。元評価株価の結果を指値へ転用せず、期間延長を採択した評価・遅延予測・保有期限や新しい採否gateにしない。損失ケースの年率が0へ近づいても損失額が減るわけではなく、資金拘束、遅延で変わる価値/分配・費用は別に検討する。

#### cash・数量と費用

[資本方針](../doctrine.md#required-return-policy)に従い、小口・上限量・現金維持の損益金額/残cashを比較する。同じ一株returnでも集中・ADV・no-addの放棄利益は異なる。

context/check/previewは同じ未拘束cashで指値全量成立する条件例で、数量未指定の上限量は採用量でない。[分配/税費用の算術](stock-assessment.md#scenario-arithmetic)に従い残cash/現金維持は無利息。全体NAV/約定予測ではなく、待機後の買付・cash利回り・費用が採否を変えるなら同一終期の別案へ反映する。

保存提案全体の比較には、買付の有無によらず当時の未拘束cashと入力/台帳時刻を示す。既存の拘束は控除済みの出発額であり、総資産・買付後の残cash・現在注文可能額ではない。旧表示の未収録を0やNAVから補わず、予定入金/未約定売却代金の加算や拘束の二重控除をしない。

保存提案の表示でも、同日起点の確定評価・指値・選択数量が揃う場合だけ、この算術でBase/Downsideの損益金額と残cash・現金維持を比べる。指値での年率と同価値の遅延感応度も併読し、原評価価格の年率・元手全体の年率・期間延長の採択と分ける。各銘柄だけが指値全量で成立する条件で、他の買付や既保有を合わせたNAVではない。元の評価株価の年率は別表示し、現在入力での再判断や旧判断の採用し直しはしない。旧表示JSONの未収録、数量/価値/起点不足を0や上限数量で補わない。

数量上限は売買代金だけから求め、買付費用を自動確保しない。既知の買付費用があれば、その支払い後も未拘束cash内に収まる数量を選ぶ。比較には確認できた費用と仮定、不明なspread/impactを分けて残し、費用の未算入を0円確認としない。

<a id="listing-and-price-basis"></a>
#### 監理・整理と買値の根拠

提案の執筆時は、判断時刻までに受領を完了したJPXの原本から、対象銘柄の「監理（確認中／審査中）」と「整理」を分けて読む。これは元Selectionの採択理由でも、現在の注文受付や換金の保証でもない。確認したページに掲載がないことと、原本・区分が読めないことを分ける。対象日、ページ取得時刻、全体受領の完了時刻を表示し、古いページを今日の指定としない。指定の記載があれば、取引所の現在の区分に加え、会社の開示で新規購入者・既保有者が何をいつ受け取るかを照合する。指定だけでTOBの成立や代金/廃止日を決めない。

指定のある対象だけ、直近90暦日の保存済みEDINET一覧を同じ判断時点で照会する。`tender_filing_references`には対象会社自身が提出した意見と、買付者がこの会社について提出した書類を分け、同じ届出の番号・提出時刻と、起点の日別一覧の受領を示す。[EDINET閲覧サイト](https://disclosure2.edinet-fsa.go.jp/WEEK0010.aspx)で提出者・日付・書類管理番号を照合し、該当本文とその後の訂正、撤回、会社・取引所の最新開示を読む。**結果報告書を見つけたことは、買付けの成立、今からの応募、残る普通株主への支払いを確認したことではない。**

参照は当時までに読めた日別の選定済み一覧に限り、照会窓と受領日数を表示する。指定がない銘柄は自動照会せず、欠けた日・窓外の登録・親子／名寄せ不明・未収録の案件は見落とし得る。出てこないことを「公開買付けなし」とせず、必要なら指定のない対象も原典で調べる。対象期間の日別一覧に判断時刻より後の再取得があれば、途中の取下げ・失敗をこのコピーから遡れない。更新された日だけを検索対象から落とすと以前の届出が復活して見えるため、当時版を復元できない旨を表示し、書類参照を返さない。

評価日・最新評価・株式単位などの根拠が失効したときは、元評価の価値を履歴として残し、現在の買付可能な上限や呼値にはしない。価格が高い、または手元資金が不足すること自体で、まだ有効な価値の上限を消さない。

#### 流動性と待機

ADVの平均と同じ窓の中央値・有効観測数を併読し、一日の急増を通常の売買規模としない。窓は共通営業日数でなく実在価格barで、欠落日は無出来高0へ埋めない。窓情報を持たない旧モデルは不明のまま引き継ぐ。中央値も板の厚み・吸収可能量ではなく、警告や数量上限を変えない。

待機では逃す利益と保持cash・他機会・回避損失・追加情報を比較する。悪材料時の逆選択/event gapも考え、約定率×Base利益だけで選ばない。価値織込済みの毀損をpenaltyへ重ねず、機会損失を事後最高値としない。ADV/日足から板・queue・impact・精密約定率を創作せず、`low <= limit`も約定保証にしない。確率には[根拠・幅・感応度](../doctrine.md#fact-analysis-separation)を示す。

<a id="wait-paths"></a>
**今買う・安い指値で待つ・現金のままを同じ元手で比べる。** 任意の `investment-judgment calculate <INPUT>` で、確定形の評価入力に次の区画を加える。架空例は2単元のうち1単元だけ成立する場合も比べる。1単元なら `partial_fill_quantity` は省く。

```yaml
price_comparison:
  price_yen: 95           # 仮の待機指値。即時案は評価に記録した参照価格
  hypothetical_quantity: 200
  waiting_terms:
    initial_cash_yen: 20100
    deadline: '2026-10-09' # 評価日より後、評価の終期まで
    lot_size: 100
    partial_fill_quantity: 100
    entry_fee_bps: 10     # 買付代金の0.1%、配当には課さない
    terminal_sale_fee_bps: 10  # 仮の終期売却の費用。買付とは別指定
    base_missed_distribution_per_share_yen: 1
    downside_missed_distribution_per_share_yen: 2
```

`waiting_paths` は同じ評価のBase / Downsideごとに即時全量購入、期限までの未成立・指定した部分成立・全量成立、現金維持の**全元手の同一終期額**を返す。注文のため取り置くと仮定した現金と、期限後に拘束を解いた残金は別。購入した分だけ費用と取得後に権利のある分配を計上する。評価日より後の参照価格や記録時刻の矛盾は待機試算に使わない。過去の参照値で今約定できることは保証しない。即時案だけ元手不足ならその終額・対即時差は不明のまま、安い指値と現金の比較は残す。未取得の分配額は各ケースで明示し、終価は同じ一株単位で仮に換金する。成立時だけ事業が悪化し得るなら、成立はDownside、未成立はBaseの行も比べる。安く買う方が即時より有利でも、現金に負ける場合がある。

会計期末や権利処理などで**評価に固定した終点**が判明しているときは、`waiting_terms.fixed_terminal_date` に同じ日を指定する。待機期限がその日より後なら成立日の権利と終期の価値を結び付けられないので試算しない。締切と終期が同日でも、その日の取得で手取や分配権が得られるかは作者が原典で確認する。確定した入金日・発注期限として扱わない。固定日を指定した時だけ、全元手の必要終額は起点からの実日数を365で割った年数で比べる。元評価の整数月の切上げ・切下げで説明できない日なら、期間だけずらさず事業仮定と評価を見直す。指定しなければ従来の整数月による近似で、出力は終点の根拠を区別する。どちらも元評価の要求率やPmaxを改訂しない。

仮定は無利息・配当再投資なし・税/impactなし、各成立分が同一指値・同一権利で取得された場合に限る。取得日で分配権利や事業価値が変われば数値を変えて比較する。たとえば公開買付けの終了後に買う少数株主には、終了した応募機会はない。完全子会社化等が予定されていれば、継続保有の利益・配当を積み上げる前に、誰が何をいつ受け取れるかを確認する。経路や受取時期が不明なら通常の終期売却で埋めない。終期の入金を確認できないとき、未入金の権利を使える現金と呼ばない。全量成立時だけの利回りは待機方針の期待利回りではない。価格の実取引可能性・板・口座・売買単位の実在・受渡し・約定確率は検証せず、Pmax・推奨・注文・保存記録を作らない。

session・前提/イベントと未約定・部分約定・新情報後の確認時点を残す。変更は[再Review](#publication-review)へ。部分約定後は実保有・残注文・cash/no-addで判断し、残数再提案・指値引上げ/延長・上限超追随を自動化しない。

<a id="price-grid"></a>
### 具体条件

価格・数量・session・前提を保存する。共通gridはJPX「その他」の保守案でTOPIX500最良呼値/注文受理を保証しない。保存時の具体条件がなければ、作者の価格上限は注文に使う指値・数量ではない。後日立会や呼値が判明しても、元の提案へ数量・取引日・注文用の参照を補わない。具体案を出すには新しい時点での確認と独立Reviewが要る。

価格条件付きの資金配分を独立Reviewしたという結論は、保存本文に明記された場合だけ読む。分類・呼値を確認できず具体条件を欠いた従来の買付案に、その結論を後から補わない。

session/見直し時点はbroker期限でなく、実期限は人間確認の取引事実。[価格・時間優先と板寄せ/ザラバ](https://www.jpx.co.jp/equities/trading/domestic/04.html)で結果が変わり、即時約定も保証しない。

<a id="holding"></a>
## 保有継続と回収

当初理由をexact参照で読み、今回の重要な一次根拠で確認する。台帳で把握している保有全体を再評価する場合は、有限の実保有を一つのレポートで比較できる。新規深掘りと対照の上限は変えない。

仮説の破綻を理由に回収するなら、その破綻を支える一次資料を評価の仮説に結び、独立Reviewで確かめる。別の事実の一次資料を確認しただけでは足りない。新たな反証を得たら、評価に根拠を追加して再査読する。

取得原価は過去の損益の説明に使うが、それだけで利確・損切り・保有を決めない。いま売っても得る配当、将来権利を取らなければ得られない分配、会社が実際に支払える根拠を分ける。短期の絶対騰落・同期間の指数と業種を、事業や分配を変える原因と混同しない。個人の損益や現金・集中も判断を左右するときは、台帳が最後に更新された日と終値の日を別々に記す。

査読済みの事業仮説は維持されていても、資金配分として回収を優先するなら、全量または一部の**条件案**を選べる。保持した場合の上振れ・今後の配当と、回収して減らせるリスクや費用を同じ株数で比較し、次に結論が変わる事実を示す。これは現在の口座や注文受付を確認した具体的な売りではなく、指値・注文数量・売却代金を設定しない。1単元しかない場合に通常立会での一部回収を勧めない。仮説崩壊や現値での残存見返り不足を証明したものとも、査読前の手掛かりとも区別する。

<a id="holding-allocation"></a>
### 保有を変えない案と、どこからいくら回収するか

回収を検討する理由がある場合にだけ、同額程度を別の銘柄・組合せから回収する案をひとつ比べる。額をそろえるために端株を売れたことにしない。含み益を確定すること、現金を増やすこと、ある業種への投資額を減らすことは別の目的である。業種の円額と、株＋現金に占める割合・残る株式に占める割合は逆方向に動き得る。台帳の業種分類を実際の事業の相関へ読み替えない。

`trade-proposal-compare-holdings`は査読前の草案（`--draft`）又は指定した保存原本（`--proposal-id ... --db ...`）と、作者が選んだ案だけを読む。維持と、各案が作者指定の同じ将来立会で、参照終値どおりに成立した仮定を比較し、注文・資金移動も、順位付けもしない。未成立なら維持案、部分成立を調べるなら別の明示数量。台帳には拘束中の現金・未完了予約があり得る。比較後の現金は買付余力ではない。分割等で株数単位が不明なら既定は未評価。`assume_unchanged_share_basis: true`は「台帳株数と同じ単位だった場合」の対照に限り、既知の分割等に反する場合は使わず、原本の未確認と実口座の状態を変えない。

```bash
uv run baibai-engine investment-judgment trade-proposal-compare-holdings cases.yaml --draft proposal.yaml
```

合成例。目標は必要な**追加**現金（税費用前）で、未指定なら過不足は出さない。

```yaml
quote_on: 2026-10-14
assumed_sale_on: 2026-10-15
dividend_rights_through: 2027-03-31
sector: 合成業種
gross_recovery_target_yen: 100000
alternatives:
  一社の一単元: {"1234": 100}
  別の一単元: {"5678": 100}
dividend_windows:
  "1234":
    known_at: 2026-10-14T10:00:00+09:00
    covered_through: 2027-03-31
    source_ref: 計画と権利日を確認した一次資料の参照・前提
    yen_per_share_by_ex_date: {2027-03-30: 12}
```

祝日・個社の停止・約定可能性はこの試算で確認しない。作者は仮定の売却立会を別途確認する。配当はこの仮定の立会で売ったときに失う**今後の権利**だけ。作者は比較終点までの全対象を同じ普通株・同じ株式単位で確認し、権利落ち日別に記す（同日分は合計）。参照終値から仮定立会までに判明している配当落ちをまたぐ株には、権利付き終値を売却代金として適用せず、予想配当分だけ値下がりするとも仮定しない。既に権利落ちした未入金分・優待を入れず、支払日を権利落ち日にしない。確認済みの無配・空集合は0だが、未指定・不明・短い確認期間はゼロではない。変わらない銘柄の将来配当は差額から消えるので全市場の入力は不要。予定配当を参照時価に足して保有の利益を作らず、減配の可能性と配当落ち後に残る価値を審査する。税・費用・流動性、売らなければ残る事業の見返りで結論が逆になるなら、既存の全体比較・不採用理由へ明記する。全量時の帳簿原価差は税額・手取りではなく、一部売却の原価を按分で補わない。

保有見直しの執筆contextは、買付報告が指した元提案の訂正・人間報告を、確認締切までの別記録として示す。対象は提案全体であり、実施報告や当初評価を取り消さず、訂正先・後発理由へ付け替えない。未連結や記録不読を訂正なしと認定しない。

- 重大なbreakはsellを優先。quote/valuation/数量basis不足はterms不足で、holdへ戻さない。
- intactは旧valuation/quote欠測でもhold可だが、当日の十分な見返りとは別。将来の幅だけで取消さない。
- 見返り十分/不足には同日起点valuationと現在算術が必要。仮説破綻による売却ではこの算術を行わないため、`remaining_reward: null` とするか、`remaining_reward` に `status: uncertain` と未確認理由を記す。仮説未評価はdefer。

保存表示で「十分な残存見返り」を確認したholdは、同日起点の確定評価・保存終値・数量basisが揃う場合だけ、その終値での保有機会費用を示す。元評価株価の年率、購入原価からの損益、売却可能価格と分け、旧表示や仮説維持だけのholdへ十分性を補作しない。現在quoteや後発評価へは差し替えない。

保存表示では判断対象の保有数量・株式単位の確認状態・原価と当時の入力/台帳時計を残す。未確認数量を注文可能量へ、旧表示の未収録を保有なしへ補わず、原価を今後の見返りの分母や売却下限にしない。 保有見直しのdeferにも、同じ保存入力にある対象保有だけを示し、判断未了を未保有・売却済み・保有継続の推奨へ読み替えない。 当初理由も同じ保存入力のexact評価参照・記述・未確認理由だけを任意表示し、今回の評価や再開条件とは分ける。当初本文の不読は固定参照を残して明示し、後発評価で補完したり保留表示を失わせたりしない。

残存見返りは今後保有する増分。受取済みcash、今売っても得る確定済み未入金配当を再算入せず、旧horizonの割直しで水増ししない。税・費用・遅延・下振れが結論を変えるなら扱う。

sell limitは作者の一株回収下限。実quoteの上下とも可能だがgridに合わせ、黙って切り下げない。全量notionalは税費用前の回収下限で予想約定額/確定cashではない。下限回収・高値待ち・継続と未約定後の再確認を記す。

具体条件付きsellも、確認済み実quote×提案数量を保存ADVと比較して既存の流動性注意を示す。下限を下げて規模を小さく見せず、quote/数量basis/ADV不足は未評価とする。価格窓・中央値・有効本数と併読する参考規模で、約定可能量・回収日数・現在の板を表さず、売却判断や全量数量を自動変更しない。旧保存の注意は書換えず、現在previewの注意を分ける。

`remaining_reward` sellは実quoteでの不足に加え、同評価・期間・今後分配を作者下限で保有する機会費用（`sell_limit_projection`）も比べる。観測quote/売却後収益ではない。下限で保有が魅力的なら下限引上げ/hold/再確認と比較してなお回収する理由をReviewする。自動Pmin・Pmax sell gate・現在十分なのにTarget到達時だけ売る条件を作らず、broken sellには無効valuationの下限算術を課さない。保存表示でも、残存見返り不足の売却に同日起点の確定評価と下限が揃う場合だけ、同じ算術を保有継続との比較として示す。元評価株価や売却後の収益と分け、旧表示・条件不足・仮説不成立を0や保有推奨で補わない。

価格下落・期間経過・回復遅延・Target到達・新規購入条件未達・他候補/集中warning単独では売らず、次候補も必須にしない。全量sellの端株/不明数量は丸めない。active予約の注文処理を別確認し、人間報告を台帳反映してtermsを再確認する。 holdと同銘柄の未完了予約には非阻止の注意を示す。cash拘束0円や期限経過を予約なし・取消済みとせず、保有判断や注意自体で台帳/注文を変更しない。保存注意と現在previewの予約状態を分ける。

<a id="publication-review"></a>
## Review・保存・preview

別作業者の内容Reviewを正規checkの`draft_sha256`へ束縛し、valid/file hashで代用しない。内容変更は再Review、入力事実変更はsnapshotも取り直す。読取時刻差だけを事実変更にしない。初回発行は書込ロックの取得後の時計で検証・保存し、ロック待ちで日付や引けをまたいだら待つ前の条件を使わない。同じ内容の同ID再試行は現在の市場を読み直さず、元の発行を返す。

提案のReviewは参照評価の独立Review完了以後に行う。評価pairの保存だけが遅れた場合は、内容の完成が遅れた場合と区別する。

保存案の対象取引日が次の立会と違う場合と、カレンダー不足で次の立会が分からない場合は別の理由で再利用を止める。執筆・check・previewで銘柄区分、次の立会、呼値規則を確認できない場合は、適用数量0、数量上限と投資後の資本比較は未確定とする。条件を満たす一株の算術は別に読める。割安の根拠や条件付きの資金比較まで失うわけではない。既保有・同銘柄の残注文・同案の買付実行が確認済みの場合も、余剰資金を重複買付の数量上限にはしない。元の指値・数量は履歴に残す。終値とその呼値での試算は現在の板・注文可能量・約定の確認ではなく、再利用不能は本人の注文が失効・取消になったことでもない。

公開時に固定scope・exact評価pair・現入力を照合する。previewは保存時の不足理由と現在の阻止理由、作者上限での算術と保存指値の再試算を分ける。旧保存を下限比較済みとせず、現在上限超でもlimit/数量を書換えない。利用不能を当時の誤りと即断せず、過去本文/hashへ現在条件を適用しない。

見送り・保留の参照評価が更新された場合も、現在previewは変更と最新評価IDを示す。旧評価の価値を現在の見送り算術へ使わず、新評価の採否・価格へ自動付替えもしない。評価参照のない未完deferは、後発評価の存在だけで完成へ進めない。

現在previewは、固定した市場判断と現在利用可能な判断の参照が異なる場合、そのIDと時計を非阻止の変更理由として示す。参照差は経済変化や個社への伝達の確認ではなく、本文が同じでも別参照として区別する。同一参照でも保存判断の基準日・情報締切・発行時刻と基準日からの日本時間の暦日経過を示す。参照不変やpreview実行を新事実の再確認・市場判断の更新と解釈しない。元判断の採否・価値・価格条件へ遡及せず、未記録の情報締切は発行時刻から補わない。

旧評価のexact読取・同ID再試行は当時の内容を保つが、新たな購入条件・残存見返りへの適用は現在の派生算術の入力検証を通す。既知の入力不整合は評価の見直しへ戻し、現在の数量・見返りを確定しない。未使用の未知観測や負利益まで除外せず、算術に依存しない仮説維持のhold・破綻のsell、見送り/保留を一律停止しない。

執筆contextでも、固定した評価が最新でなければ現在quoteの見返りを返さない。元pairと最新IDは比較材料として残し、新評価への束縛・採用を自動化しない。旧上限は元評価に残し、現在の買付に使える上限としては返さない。

saved/current warningを分け、人間へ示す。既知factor比率が下限ならcoverageを示す。保有時価/NAVと取引は[Ledger](../../.agents/skills/ledger-record/SKILL.md)に従う。

## 提案の訂正と人間の報告

[非購入報告](../../engine/src/baibai_engine/investment_judgment/trade_proposal/record_contracts.py)はexact提案への別記録でno_actionではない。本人の言葉・報告/対象時点・要約を分け、未発注/取消/未約定/永久却下を推測せず、提案/Review/台帳を変えない。

訂正・報告は元提案を持つ既存Appへの追記で、不在・未対応のstoreを作成/移行しない。失敗時は空Appを初期化せず、`--db`が元提案の保存先かを確認する。

誤記録はexact参照/理由付き追記訂正で最新候補から除く。残りは元の基準日・発行時刻・ID順で選び、関連旧提案の優先や訂正時刻の再順位付けをしない。原本/訂正はIDで読め、完了Operationは不変。誤記録と明示訂正した提案の現在previewは使用不可とし、現在算術へ再適用しない。元の保存行動/条件は残し、訂正先を自動適用せず、本人の非購入報告や後続提案の存在だけを誤記録としない。保存表示/previewは同じ訂正集合、人間報告は別表示とし、新推奨/適格性回復や当日refreshの代わりにしない。
