# Doctrine

Baibai Loopは健全な企業の割安な機会を継続的に探し、日本個別株の現物で資本を運用する。保守的な価値評価、支払価格、成立条件、確からしさ、実現までの時間から上振れ・下振れを比較する。株価下落だけを割安とせず、上昇中でも価値に対して安い企業を対象にする。

<a id="investment-strategy"></a>
## 投資と人間の役割

AIは人間の明示開始から有限対象を調べ、評価・独立Review・具体的な提案まで進める。最終裁定とbroker操作は人間が行う。自動発注、信用、借入、空売りは行わない。根拠付きの見送りや未確定は正常な成果で、予算消化・投資率・銘柄数をノルマにしない。

恒久的な企業価値毀損の回避を優先する。回復可能な赤字、下方修正、循環悪化、不利なscenarioの存在を一律の除外理由にせず、一時的な含み損や長い資金拘束を許容する。健全さだけで高過ぎる価格や回収不能なcaseを正当化しない。固定含み損率、金額loss budget、年間損失停止、drawdown kill switchは置かない。

保有期間は先に固定せず、評価期間はscenarioの比較窓として扱う。期限売却はしない。持続可能な配当を選好するが必須とせず、無配の価値機会も対象にする。通常経路では既保有tickerへの追加購入を提案せず、別評価IDでも迂回しない。人間が実行した追加購入・部分売却は事実として記録する。

割安な指標を買うのでなく、普通株主へ帰属する将来価値を買う。持続する現金創出、収益回復、資本解放、価値を増やす再投資のうち結論を左右する経路を選ぶ。全経路を全社へ要求せず、最も高い価値を出す式を選ばない。四Approachがあること自体を経済的分散の証拠にしない。

利益の反復性、資産の帰属、再投資費用と回収期間を価格に合わせず組み立てる。回復・成長をゼロにすることが常に保守的とは限らず、会社計画も実現値ではない。仮定が崩れる経済状態、判断を反転させる条件を原典へ結び付ける。12か月へ固定せず、要求率を通すために期間を延ばさない。

有限な調査時間は、上振れの大きさだけでなく、重要な問いに答えが得られ、その答えで判断が変わるかへ配分する。機械順位の極端値や同じ資料を繰り返すことを深掘りとしない。候補外の対照も必要な範囲で比較し、対象数や戦略別の枠を埋めない。

<a id="required-return-policy"></a>
## 要求年率と資本

要求年率は案件ごとに作者が根拠を説明する正の有限値。6%は比較の目安で、一律floor・自動入力値ではない。6%未満も選べるが、率だけで購入せず、現在の価格から残る見返り・成立条件・永久損失・現金維持や代替案を比べる。機械E[r]や固定8.5%較正帯とは別の仮定である。要求率の変更は新しい評価と独立Reviewにし、過去評価・提案・取引を改変しない。

約500万円、月40万円の予定、10〜20銘柄は運用イメージであり、予定入金はcashではない。通常5〜8%程度、1回20〜30万円のguideもquotaやNAV連動の自動sizingではない。guide上限と確認済みcashで単元を求め、guideを超える1単元でもcash内ならwarning付き候補となる。下限に合わせて増やさない。

集中・ADV・cash20%等のwarningは人間へ示す。自動売却や数量縮小へ格上げせず、企業根拠の不足を小口購入やwarning受容で免除しない。未確認の保有時価や未約定売却代金で分母・cashを作らない。追加禁止には機会費用があるが、最適性を実証したとは扱わない。

保有は重要な投資理由の不成立、または確認済みの残存見返り不足によりsellを検討する。仮説維持のholdと当日起点の十分な見返りを主張するholdを区別する。価格下落、期間経過、回復遅延、Target到達、新規購入条件未達、他候補・集中warning単独では売らない。次の候補がなくても現金を回収できる。詳細は[Investment Proposal](reference/investment-proposal.md#holding)。

<a id="fact-analysis-separation"></a>
## 根拠と見積り

観測、規則による導出、機械見積り、AIの判断を分ける。条件付きreturnや機械E[r]を企業scenarioの確率加重期待値へ読み替えず、確からしさは根拠と反証で説明する。根拠のない精密な確率や言葉だけの分類規則を増やさない。

不確実性をなくすことを購入の前提にしない。重要な未知も、確認した事実と区別して経済的影響・条件付き見返り・引き受ける理由を説明できれば提案へ進める。高いBase利回りだけでなく、その経路を中心に置く根拠と反対条件を比較する。根拠のない数字や未確認事実の確認済み扱いで不足を消さず、採否を決められない場合は何が不足かを限定して保留する。

マクロは共通条件と個社への伝達を分ける。変化が小さくても高い調達費や借換期限を無影響にせず、基準価値と独自マクロ仮説による差を示す。同じリスクを利益・倍率・要求率へ無説明に重複算入しない。環境の欠測だけで正常な他領域を止めず、残る不確実性が見返りに見合うかを判断する。

AIを含む産業構造変化は、それを外すと価値・永久損失・反証・提案が変わる場合に扱う。「AIを使う」「市場が成長する」だけで利益や倍率を上げず、専用score・theme枠を作らない。外部評価の転載数や同じ価格情報を独立票にしない。

実運用の結果を見積りへ戻す。資産全体の成果はcash・未売却損益・配当・記録済み費用と税を含むPortfolio Outcomeで測り、個別予測と歴史較正を区別する。小標本や短期成績で戦略の収益優位を主張せず、方法の比較は[較正](reference/estimate-calibration.md)に従う。

<a id="development-investment-policy"></a>
## 開発・設計・レビュー

- 具体的な利用場面と改善効果から考え、実装・運用・理解・将来変更の負担に見合う最も単純な方法を採る。現行仕様も無条件に正しい前提にしない。
- 自動化・共通化の前に処理をなくせないか考える。未確定の将来用途のために基盤・設定・状態・registryを増やさない。旧構造へ継ぎ足さず、現在の責務に合わせて置き換える。
- 不要な仕様・互換分岐はコード・test・文書と一緒に削る。一回の移行や比較を恒久機構にせず、必要ならデータを移行・再構築する。失う範囲を明示し、復元不能な本番削除は実行直前に対象を確認する。
- 過剰な防御・監査・二重検証は既存分も見直す。実害と発生可能性、代替、維持費から判断し、推測上の稀なcaseで実用化を止めない。明らかな改善へ専用の実証基盤を要求しない。
- レビューは実装・caller・test・設定・運用を横断して意味と連携を見る。所見数・test数・変更量を成果にせず、判断を変える根拠を示す。

## 現在の非目標

機械学習によるスコアリング、閾値の網羅探索、3か月未満のforward-backtestによるscreen最適化、ETF/投資信託/海外株の運用、口座・税制やbroker会計の完全複製、外部向け汎用データ配信・公開MCP・書込APIは持たない。所有者用のread-only Webと長期の見積り較正は範囲内である。longfolioは別目的で連携・重複確認を持たず、投資助言サービスにはしない。
